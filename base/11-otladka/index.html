    11. Ловушки и отладка¶

    Коротко

    Ошибка Python — читать последнюю строку (что случилось) и номер строки над ней (где). Хуже — ответ без ошибки, но неверный: проверяйте программу на примере из условия, печатайте промежуточные значения, сверяйте вторым способом. Подозрительно, если ответ равен границе range, если ничего не напечаталось, если ответ дробный (.0). Нет ответа за 2–3 минуты — Ctrl+C и способ быстрее.

    Как пробовать примеры

    Строки с >>> набирайте в окне IDLE Shell и нажимайте Enter. Строки с ... — тело цикла или функции: набирайте с отступом, а в конце нажмите Enter ещё раз на пустой строке. Каждый пример на странице проверен запуском (Python 3.11 и 3.12).

    Как читать сообщение об ошибке¶

    Когда программа падает, Python печатает красный текст. Важны две вещи: последняя строка — тип ошибки и пояснение, и line N над ней — в какой строке программы это случилось (в IDLE строка подсвечивается, а Alt+G — перейти к строке по номеру).

    >>> a = [5, 8, 3]
>>> [a[i] + a[i + 1] for i in range(len(a))]
Traceback (most recent call last):
  ...
IndexError: list index out of range

    Две суммы посчитались, третья — нет: у последнего элемента нет соседа — пары соседних — range(len(a) - 1) (§3).

    Ошибка Что значит Частая причина на ЕГЭ
    SyntaxError, IndentationError программа записана неправильно, не запустилась забыто : после if/for/def (expected ':'), лишний или недостающий отступ, = вместо == в if, незакрытая скобка ('(' was never closed — Python показывает строку с открывающей скобкой)
    NameError: name 'x' is not defined такого имени нет опечатка, русская буква в имени, забыт import, переменная заведена ниже
    IndexError: … index out of range номер за концом списка или строки a[i + 1] у последнего, пустая строка s[0], список вершин короче номеров (№23)

    Типичные синтаксические ошибки — проверим, что скажет Python (compile проверяет запись программы, не выполняя её):

    >>> compile('if x = 5:\n    print(x)', 'prog', 'exec')
Traceback (most recent call last):
  ...
SyntaxError: invalid syntax. Maybe you meant '==' or ':=' instead of '='?
>>> compile('for i in range(10)\n    print(i)', 'prog', 'exec')
Traceback (most recent call last):
  ...
SyntaxError: expected ':'

    Тихие ошибки: ответ есть, но неверный¶

    Самое опасное — программа отработала и напечатала число, а оно неверное. Признаки, при которых стоит перепроверить:

    • Ответ равен границе перебора (range(1, 10000) → 9999): «наибольшее» молча печатает границу. Расширить range и запустить снова — ответ не должен меняться (№11: 9999 вместо 32 768; §3).
    • Ничего не напечаталось — ни одно значение не подошло: граница мала, условие перевёрнуто или открыт не тот файл.
    • Ответ дробный (183235.0) — где-то / вместо // (§1); в бланк — целое без .0.
    • Ответов несколько, а нужен один, или ответ слишком «круглый» (0, 1) — неверное условие в if.
    • Ответ отрицательный там, где отрицательного быть не может, — % или // на отрицательных (§1).

    Частые тихие ошибки по разделам — в «Типичных ошибках» каждого раздела базы и каждой карточки. Самые частые:

    Ошибка Что происходит Где подробно
    range(1, N) вместо range(1, N + 1) последнее число не проверено §3
    / вместо // дробный ответ, на больших числах — потеря цифр §1
    not w <= x и приоритет not/and/or условие не то, что в задаче §2
    b = a.sort() в b — None §5
    max по всем, а не по подходящим другой максимум (№17: 177 727 вместо 174 933) §5
    int(x) у дробной координаты/суммы 4 вместо 5 (4.999999999999999) §1, §9
    bin(n).count('0') на 1 больше (ноль из 0b) §7
    [[0] * m] * n все строки таблицы — одна и та же §5
    первая строка файла — количество лишнее или потерянное число §8
    permutations без sorted слова не по алфавиту §9

    Проверка на примере из условия¶

    Почти в каждом номере есть пример: «например, для N = 13 получится R = 27», «для 3 камней Петя выигрывает…», «в файле из 6 чисел ответ 2». Запустите программу на нём прежде чем на настоящих данных. Удобно сделать из шага задачи функцию и сравнить:

    >>> def R(n):
...     s = bin(n)[2:]
...     s = s + str(s.count('1') % 2)
...     return int(s, 2)
...
>>> R(13)
27
>>> R(13) == 27
True

    Совпало с примером — шаги переписаны верно; не совпало — ищите ошибку, пока данных мало. Для задач с файлом — сохранить пример из условия в маленький файл (proba.txt) и запустить программу на нём (§8).

    Печатать промежуточные значения. Если ответ не сходится — print внутри цикла на нескольких первых шагах: видно, что программа «думает» на самом деле. Много строк — ограничить: if i < 10: print(i, x). После проверки печать убрать (или поставить # в начале строки — Alt+3 в IDLE).

    >>> a = [12, -35, 47, 50]
>>> for i in range(len(a) - 1):
...     print(i, a[i], a[i + 1], (a[i] + a[i + 1]) % 3)
...
0 12 -35 1
1 -35 47 0
2 47 50 1

    Второй способ. Для важного ответа — посчитать иначе: перебором на маленьких данных против формулы (№16, №8), программой против таблицы (№3, №18, №22), двумя разными программами (№27). Совпали — почти наверняка верно. Так сверены шаблоны карточек этого справочника.

    Сколько ждать и когда бросать¶

    Простой цикл проходит около 10 млн шагов за секунду-другую (на слабом компьютере — в несколько раз медленнее). Если программа молчит дольше 2–3 минут — Ctrl+C (в окне IDLE Shell; Python напишет KeyboardInterrupt) и способ быстрее. Замеры по номерам (Python 3.11 и 3.12, обычный ноутбук):

    Задача Медленный способ Время Быстрый способ Время
    №8, 2,5 млрд слов перебор product 8,5 мин «виды цифр» на местах и умножение мгновенно
    №13, 17 млн программ рекурсия без кэша 35 с @lru_cache мгновенно
    №16, интервал 10⁹ чисел перебор не дождаться понять, что считает функция, и считать без перебора мгновенно
    №25, числа около 10⁹ все делители 16 с на одно число разложение на множители 10–12 с на пять
    №25, 770 млн кратных fnmatch по каждому минут десять строить числа по маске (карточка №25) быстро
    №6, сетка большой фигуры точка в каждом узле 1–1,5 мин точка через 5 шагов 0,2 с
    №24, Крылов, 5 млн символов, ответ — 25 тыс. символов двойной цикл 24 мин (и 17 мин) окна между нужными цифрами 2 с
    №17, 10⁵ чисел min(a) внутри цикла ≈ 100 с m = min(a) до цикла мгновенно

    Кроме времени, бывает память: кэш огромных чисел (№16, «факториалы» ЕГЭ-2026) занимает гигабайты, и слабый компьютер падает с MemoryError — сокращать выражение вручную (§6).

    Python может молча закрыться. Глубокая рекурсия с lru_cache и setrecursionlimit на Python 3.11 в Windows заканчивается без ответа и без сообщения об ошибке (§6). Если программа с рекурсией «закончилась», ничего не напечатав, — причина, скорее всего, эта: прогрев вместо поднятого предела.

    Перед тем как записать ответ¶

    • Ответ — то, что спрашивают: «наименьшее N» или «R при наименьшем N»; количество или сумма; число в десятичной системе или запись.
    • Два числа — в том порядке, что в вопросе (№17: количество, потом максимум; №18 бывает «сначала минимум»); через пробел, без запятых.
    • Целое — без .0; «целая часть» — int (не округление).
    • Программа на примере из условия дала тот же ответ.
    • Граница range расширена — ответ не изменился.
    • Для задач с файлом — открыт тот файл (A или B в №27, свой номер варианта).

    Типичные ошибки¶

    Скрытые ловушки — проверены запуском

    • Не прочитана последняя строка ошибки — в ней тип и причина; номер строки — над ней.
    • SyntaxError — читать пояснение: expected ':' — забыто двоеточие, '(' was never closed — незакрытая скобка (в строке, которую показал Python), Maybe you meant '==' — = вместо == в if.
    • Ответ равен границе range — граница мала (№11: 9999 вместо 32 768).
    • Ничего не напечаталось — ни одно значение не подошло или открыт не тот файл.
    • Дробный ответ …0 — / вместо // (§1, демо-2027 №25).
    • Нет проверки на примере из условия — ошибка в шагах видна только на нём.
    • Ждать бесконечно — после 2–3 минут Ctrl+C и способ быстрее (№8, №13, №16, №24, №25).
    • Рекурсия закончилась без ответа и без ошибки — глубокая рекурсия на 3.11 в Windows (§6); прогрев.
    • Отладочная печать в цикле на миллионы шагов — сама тормозит программу; печатать первые шаги.

    Где встречается¶

    Везде. Больше всего тихих ошибок — в №2 (логика), №5 (что именно спрашивают), №8 (огромный перебор), №13 и №16 (рекурсия), №17 (максимум по подходящим), №24 (регулярки, долгий запуск), №25 (деление, множители), №27 (выбор R).
