    1. Числа и арифметика¶

    Коротко

    // — целая часть от деления (вниз), % — остаток, ** — степень, / — всегда дробное (в ответ — только //). Целые числа в Python любой длины и точные, дробные — приближённые: сравнивать и брать целую часть через round(x, 6). Округление — по смыслу задачи: вниз //, вверх ceil, к ближайшему round (но round(10.5) = 10).

    Как пробовать примеры

    Строки с >>> набирайте в окне IDLE Shell (то, что открывается при запуске IDLE) и нажимайте Enter — следующей строкой Python напишет ответ, как здесь. Набирать самим полезнее, чем копировать: так запоминается. Каждый пример на странице проверен запуском (Python 3.11 и 3.12).

    Целые и дробные числа¶

    В Python два вида чисел: целые (int: 5, -17, 2027) и дробные (float: 3.5, 0.1, 2.0). Дробная часть пишется через точку, не через запятую. Деление / всегда даёт дробное — даже когда делится нацело:

    >>> 7 / 2
3.5
>>> 6 / 2
3.0
>>> 7 // 2
3
>>> 7 % 2
1

    3.0 и 3 для Python — одно и то же число, но в бланк ответа 3.0 писать нельзя, а range(3.0) — ошибка. Поэтому, если ответ — целое число, делите через //.

    Действия¶

    Знак Что делает Пример Результат
    + - * сложение, вычитание, умножение 2 + 3 * 4 14
    / деление (дробное) 7 / 2 3.5
    // целая часть от деления (вниз) 17 // 5 3
    % остаток от деления 17 % 5 2
    ** степень 2 ** 10 1024

    Порядок действий — как в математике: сначала **, потом *, /, //, %, потом + и -; при равенстве — слева направо. Сравнения (==, <…) — после арифметики, поэтому x % 2 == 0 работает без скобок. Две тонкости со степенью:

    >>> -2 ** 2
-4
>>> (-2) ** 2
4
>>> 2 ** 3 ** 2
512

    Минус перед числом слабее степени (-2 ** 2 = −(2²)), а несколько ** подряд считаются справа налево (2 ** 9 = 512). Сомневаетесь — ставьте скобки.

    Сокращённые записи: x += 5 — то же, что x = x + 5; так же -=, *=, //=, %=.

    Целое деление и остаток: цифры числа¶

    a // b — сколько раз b целиком помещается в a, a % b — что осталось. Всегда верно a == (a // b) * b + a % b.

    Нужно Код Для x = 2027
    последняя цифра x % 10 7
    две последние цифры x % 100 27
    отбросить последнюю цифру x // 10 202
    делится на k x % k == 0 x % 7 == 0 → False
    чётное x % 2 == 0 False
    частное и остаток сразу divmod(x, 10) (202, 7) 
    >>> x = 2027
>>> x % 10, x % 100, x // 10
(7, 27, 202)
>>> divmod(x, 10)
(202, 7)

    Все цифры числа — по одной с конца: берём последнюю (% 10) и отбрасываем её (// 10), пока число не кончится. То же работает в любой системе счисления — вместо 10 подставьте основание (см. №14):

    >>> x = 2027
>>> s = 0
>>> while x > 0:
...     s += x % 10
...     x //= 10
...
>>> s
11

    Отрицательные числа¶

    // округляет вниз (к меньшему), а не «отбрасывает дробную часть», и остаток % в Python всегда того же знака, что делитель — для деления на 10 он неотрицательный:

    >>> -7 // 2
-4
>>> int(-7 / 2)
-3
>>> -17 % 10
3
>>> abs(-17) % 10
7

    Поэтому «последняя цифра» и «оканчивается на…» у чисел, которые бывают отрицательными (№17), — только от abs(x): abs(x) % 10 == 7, abs(x) % 100 == 25.

    Большие числа¶

    Целые в Python — любой длины и точные: 2 ** 100 посчитается до последней цифры. А дробные — это примерно 16 верных цифр, поэтому / на больших числах молча ошибается или вовсе падает:

    >>> 2 ** 100
1267650600228229401496703205376
>>> (10 ** 17 + 5) // 3
33333333333333335
>>> int((10 ** 17 + 5) / 3)
33333333333333336
>>> 10 ** 400 / 21
Traceback (most recent call last):
  ...
OverflowError: integer division result too large for a float

    Правило: если числа большие (№14, №16) — ни одного /, только // и %.

    Лимит 4300 цифр. В Python 3.11 и новее (и в 3.9 и 3.10 с обновлений осени 2022) нельзя напечатать или перевести в строку число длиннее 4300 цифр. Считать с ним (%, //) можно, а print, str, len(str(…)) — нет:

    >>> n = 10 ** 5000
>>> n % 7
2
>>> len(str(n))
Traceback (most recent call last):
  ...
ValueError: Exceeds the limit (4300...) for integer string conversion...
>>> import sys
>>> sys.set_int_max_str_digits(0)
>>> len(str(n))
5001

    sys.set_int_max_str_digits(0) снимает лимит — одна строка в начале программы (№14). В старом Python (3.9 до 3.9.14) такой команды нет, но там нет и лимита.

    Запись больших чисел. 10 ** 9 и 1_000_000_000 — целые. А 1e9 — дробное, и в range его не подставить:

    >>> 1e9
1000000000.0
>>> range(1e9)
Traceback (most recent call last):
  ...
TypeError: 'float' object cannot be interpreted as an integer

    Дробные числа неточны¶

    Дробные хранятся в двоичном виде, и простые десятичные дроби вроде 0,1 записываются с крошечной ошибкой. Обычно её не видно, но она всплывает при сравнении и при взятии целой части:

    >>> 0.1 + 0.2
0.30000000000000004
>>> 0.1 + 0.2 == 0.3
False
>>> round(0.1 + 0.2, 6) == 0.3
True
>>> 30.6 + 83.1 + 5.3
118.99999999999999
>>> int(30.6 + 83.1 + 5.3)
118
>>> int(round(30.6 + 83.1 + 5.3, 6))
119

    Правило: дробный результат сначала округлить до 6 знаков, потом сравнивать или брать целую часть: int(round(x, 6)). Так в №23 (сумма дробных длин дорог: 3362 вместо 3363 без round) и в №6 (координаты Черепахи). Проценты лучше считать в целых: V * 30 // 100, а не V * 0.3 или V * (1 - 0.7):

    >>> 10 * (1 - 0.7)
3.0000000000000004
>>> import math
>>> math.ceil(10 * (1 - 0.7))
4
>>> 10 * 30 // 100
3

    Округление¶

    Нужно Код 7.5 -7.5
    отбросить дробную часть int(x) 7 -7
    вниз (к меньшему) math.floor(x), для целых a // b 7 -8
    вверх (к большему) math.ceil(x) 8 -7
    к ближайшему round(x) 8 -8
    до k знаков round(x, k)

    math.floor и math.ceil — из модуля math: в начале программы import math (или from math import ceil).

    round — «банковское» округление: ровно половина округляется к чётному, а не всегда вверх. В №7 «к ближайшему целому» при ровно ,5 — проверьте, нет ли такого случая:

    >>> round(10.5)
10
>>> round(11.5)
12
>>> round(7.5)
8

    Вверх без дробей. Для целых a и b деление с округлением вверх — (a + b - 1) // b, например «сколько байт на 43 бита» — (43 + 7) // 8. Тот же ответ даёт math.ceil(43 / 8) — но только с /, не с //:

    >>> import math
>>> (43 + 7) // 8, math.ceil(43 / 8)
(6, 6)
>>> math.ceil(6 * 7 // 8)
5

    (42 бита — это 6 байт, а 6 * 7 // 8 уже округлило вниз до 5, ceil опоздал.)

    Какое округление нужно — решает условие (№7, №11):

    В условии Округление
    «наибольшее количество» (цветов, снимков, символов), «поместится» вниз: //
    «наименьшее целое число Кбайт», «сколько потребуется», «не менее» вверх: ceil
    «бит на символ», «бит на цвет» (N вариантов) вверх: ceil(log2(N))
    «целая часть» int(…) (у дробного результата — int(round(x, 6)))
    «округлите до ближайшего целого» round(…)

    Степени, корни, логарифмы¶

    >>> import math
>>> math.log2(1024)
10.0
>>> math.log2(1568)
10.614709844115207
>>> math.ceil(math.log2(1568))
11
>>> math.isqrt(99), math.isqrt(100)
(9, 10)
>>> 64 ** (1 / 3)
3.9999999999999996
>>> round(64 ** (1 / 3)) ** 3 == 64
True
    • Бит на N вариантов — ceil(log2(N)): 1568 цветов — 11 бит, а int(log2(1568)) = 10 (№7, №11).
    • Целый квадратный корень — math.isqrt(n): точный для любого n. Делители — до корня включительно: range(1, math.isqrt(n) + 1) (№25). «Полный квадрат?» — math.isqrt(n) ** 2 == n.
    • Корень через дробную степень неточен: int(64 ** (1/3)) = 3. Проверять «полный куб?» так: round(n ** (1/3)) ** 3 == n (№9).

    abs, min, max, sum¶

    >>> abs(-17)
17
>>> min(3, -5, 2), max(3, -5, 2)
(-5, 3)
>>> max([4, 9, 1])
9
>>> sum([1, 2, 3]), sum(range(1, 101))
(6, 5050)

    min и max принимают и несколько чисел, и список. От пустого списка — ошибка ValueError (условие ни разу не выполнилось или открыт не тот файл, см. №17).

    Подробнее: НОД, НОК, точные дроби

    НОД и НОК — math.gcd и math.lcm (Python 3.9+). «Делится и на a, и на b» = делится на НОК(a, b), а не на произведение: числа, кратные 4 и 6, идут с шагом 12, а не 24 (№25).

    >>> import math
>>> math.gcd(12, 18), math.lcm(4, 6)
(6, 12)
>>> math.lcm(31, 2031)
62961

    Точные дроби — Fraction из модуля fractions. Нужны, когда посередине вычислений появляется дробь, а ответ в конце целый (№16: «G(n) = n / 4 + 18», потом результат умножают). // посередине молча теряет дробную часть, / на больших числах теряет цифры, Fraction считает точно:

    >>> from fractions import Fraction
>>> Fraction(10, 4)
Fraction(5, 2)
>>> 10 // 4 * 8, Fraction(10, 4) * 8
(16, Fraction(20, 1))
>>> int(Fraction(10, 4) * 8)
20

    Сколько бит в числе — n.bit_length() (без перевода в строку): (1024).bit_length() = 11. Для n ≥ 2 ceil(log2(n)) = (n - 1).bit_length() — без дробей (№11).

    Типичные ошибки¶

    Скрытые ловушки — проверены запуском

    • Ответ с «.0». 351261495 / 1917 = 183235.0 — если ответ целый, делите // (№25, демоверсия 2027).
    • / на больших числах. int((10**17 + 5) / 3) ошибается в последней цифре, 10**400 / 21 — OverflowError. Только // (№14, №16).
    • int ≠ // у отрицательных. int(-7 / 2) = −3, -7 // 2 = −4.
    • Целая часть суммы дробей — от всей суммы: int(15/2 + 15/2) = 15, а 15//2 + 15//2 = 14 (№16).
    • % у отрицательных. -17 % 10 = 3: последнюю цифру брать от abs(x) (№17).
    • int от дробного результата. int(118.99999999999999) = 118 — сначала round(x, 6) (№6, №23).
    • Проценты через дроби. ceil(10 * (1 - 0.7)) = 4 вместо 3 — считать в целых: V * 30 // 100 (№7).
    • round(10.5) = 10 — половина округляется к чётному (№7).
    • int(log2(N)) вместо ceil — 10 бит на 1568 цветов вместо 11 (№7, №11).
    • ceil после //. ceil(6 * 7 // 8) = 5 вместо 6 — внутри ceil только / (№11).
    • Корень через ** 0.5 или ** (1/3) — int(64 ** (1/3)) = 3. Квадрат — math.isqrt, куб — через round (№9, №25).
    • «Делится на a и на b» — шаг НОК, не a * b (№25).
    • -2 ** 2 = −4 и 1e9 — дробное (range(1e9) — ошибка).
    • Лимит 4300 цифр у print и str в Python 3.11+ — sys.set_int_max_str_digits(0) (№14).

    Где встречается¶

    №5 (чётность, %), №6 (дробные координаты), №7 и №11 (округления, log2), №9 (полный куб), №13 (цифры числа, деление пополам вверх), №14 (большие числа, цифры в системе счисления), №16 (/ и //, Fraction), №17 (% у отрицательных), №23 (round у суммы дробных), №25 (делители, НОК, // в ответе).
