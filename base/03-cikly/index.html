    3. Циклы¶

    Коротко

    range(a, b) — числа от a до b - 1: конец не входит, «от 1 до N» — range(1, N + 1). Наименьшее — первое подходящее и break, наибольшее — последнее подходящее (без break). Если ответ равен границе range — граница мала: расширить и проверить снова. while — «пока условие верно»; нет ответа за 2–3 минуты — Ctrl+C и искать способ быстрее.

    Как пробовать примеры

    Строки с >>> набирайте в окне IDLE Shell и нажимайте Enter. Строки с ... — тело цикла: набирайте с отступом, а в конце нажмите Enter ещё раз на пустой строке — тогда цикл выполнится. Каждый пример на странице проверен запуском (Python 3.11 и 3.12).

    for и range¶

    for повторяет строки с отступом для каждого значения по очереди. Чаще всего значения берут из range:

    Запись Числа Пример
    range(n) 0, 1, …, n − 1 (всего n) range(5) → 0 1 2 3 4
    range(a, b) a, a + 1, …, b − 1 range(1, 6) → 1 2 3 4 5
    range(a, b, k) с шагом k, пока меньше b range(10, 30, 5) → 10 15 20 25
    range(b, a, -1) обратно: b, b − 1, …, a + 1 range(5, 0, -1) → 5 4 3 2 1 
    >>> list(range(5))
[0, 1, 2, 3, 4]
>>> list(range(1, 6))
[1, 2, 3, 4, 5]
>>> list(range(10, 30, 5))
[10, 15, 20, 25]
>>> list(range(5, 0, -1))
[5, 4, 3, 2, 1]
>>> len(range(10, 100))
90

    list(range(…)) здесь — только чтобы увидеть числа; в программе пишут for x in range(…):. Числа в range — только целые: range(1e9) и range(n / 2) — ошибка (§1).

    Сумма и счётчик — переменная до цикла, в цикле к ней добавляем:

    >>> s = 0
>>> for i in range(1, 11):
...     s += i
...
>>> s
55
>>> k = 0
>>> for x in range(1, 101):
...     if x % 3 == 0 or x % 5 == 0:
...         k += 1
...
>>> k
47

    Если нужно и количество, и максимум, и сумма подходящих — удобнее собрать их в список и спросить len, max, sum (§5): так не надо думать, с чего начинать максимум.

    Границы перебора¶

    Самая частая ошибка с циклом — не та граница. Переводим слова условия:

    В условии range
    «натуральные», «положительные» до N range(1, N + 1)
    «неотрицательные», «целые неотрицательные» range(0, …)
    «не превышающее 2030» range(1, 2031)
    «меньшее 2000» range(1, 2000)
    «N больше 20» range(21, …)
    «трёхзначные», k-значные range(100, 1000), range(10 ** (k - 1), 10 ** k)
    «из отрезка [a; b]» (включительно) range(a, b + 1) — в нём b - a + 1 чисел
    цифры системы счисления с основанием b range(b)
    «целое A», «любые целые x» и с отрицательных: range(-1000, 1001)
    кратные K до N range(K, N + 1, K) — не с 0: 0 не натуральное

    Граница «≤ 9·10⁷» включена — само 90 000 000 может подойти: range(…, 90_000_001) (№16). «Натуральные N» — с 1, а не с 0: в демоверсии №5 перебор с 0 даёт 27 вместо 28.

    Когда граница не задана (№15, №11 «наибольшее…», №5), её выбираем сами — с запасом: перебор должен заходить дальше всех чисел из условия. А потом — проверка: если ответ совпал с концом range, это не ответ, а граница. Расширяем и запускаем снова:

    >>> for n in range(1, 500):
...     if n * n <= 10 ** 6:
...         otvet = n
...
>>> otvet
499
>>> for n in range(1, 5000):
...     if n * n <= 10 ** 6:
...         otvet = n
...
>>> otvet
1000

    Ошибки не было — программа просто напечатала 499. Так в №11 перебор range(1, 10000) молча печатает 9999 вместо 32 768, а в №15 ответ «550» при границе 550 оказывается 1100.

    Наименьшее и наибольшее¶

    • Наименьшее — перебираем по возрастанию, на первом подходящем печатаем и выходим из цикла break.
    • Наибольшее — запоминаем каждое подходящее (otvet = n); после цикла в otvet останется последнее. Или перебираем по убыванию и выходим на первом.
    >>> for n in range(1, 1000):
...     if n * n > 2027:
...         print(n)
...         break
...
46
>>> for n in range(10, 100):
...     if n % 7 == 0:
...         otvet = n
...
>>> otvet
98
>>> for n in range(99, 9, -1):
...     if n % 7 == 0:
...         print(n)
...         break
...
98

    Если ни одно число не подошло, «наименьшее» не напечатает ничего, а «наибольшее» упадёт с NameError: name 'otvet' is not defined — значит, ответ за границей range (№15).

    Наименьшее значение результата — не то же, что результат при наименьшем N. В №5 «наименьшее R, большее 95» — R «скачет» при росте N, поэтому собираем все подходящие R в список и берём min (в демоверсии первое найденное R — 115, а наименьшее — 100).

    while: пока условие верно¶

    while повторяет тело, пока условие верно. Удобен, когда число шагов заранее неизвестно:

    >>> n = 1000
>>> k = 0
>>> while n >= 10:
...     n //= 2
...     k += 1
...
>>> n, k
(7, 7)

    Внутри цикла что-то обязательно должно менять условие (здесь — n), иначе цикл бесконечный: программа «висит». Прервать — Ctrl+C в окне IDLE Shell.

    «Первое число, больше X» (№25) — while True и break; сначала увеличиваем, потом проверяем, тогда первым проверится X + 1:

    >>> n = 2027
>>> while True:
...     n += 1
...     if n % 7 == 0 and n % 2 == 1:
...         break
...
>>> n
2037

    break выходит из цикла сразу; continue пропускает остаток тела и переходит к следующему шагу.

    Перебор строки, списка, файла¶

    for умеет идти не только по числам — по символам строки, элементам списка, строкам файла (§8). Если нужен ещё и номер — enumerate (второй аргумент — с какого номера считать):

    >>> for c in 'ЕГЭ':
...     print(c)
...
Е
Г
Э
>>> for i, c in enumerate('ЕГЭ', 1):
...     print(i, c)
...
1 Е
2 Г
3 Э

    Номер «в списке, куда попали не все» (№8: «номер слова среди подходящих») — свой счётчик внутри if, а не enumerate: enumerate считает все слова подряд (Решу ЕГЭ 35466: 83 вместо 23).

    Перебор логической переменной (№2) — for x in 0, 1: (то же, что range(2)).

    Вложенные циклы¶

    Цикл в цикле перебирает все сочетания. Таблица истинности (№2) — три вложенных цикла по 0 и 1:

    >>> print('x y z')
x y z
>>> for x in 0, 1:
...     for y in 0, 1:
...         for z in 0, 1:
...             if (x <= y) and (not z):
...                 print(x, y, z)
...
0 0 0
0 1 0
1 1 0

    Соседние элементы (№17) — по номерам, и последний номер — len(a) - 2, иначе a[i + 1] выйдет за конец:

    >>> a = [5, 8, 3, 9]
>>> for i in range(len(a) - 1):
...     print(a[i], a[i + 1])
...
5 8
8 3
3 9

    Тройки соседних — range(len(a) - 2). Все пары (каждая один раз) — второй номер начинается после первого:

    >>> a = [5, 8, 3, 9]
>>> k = 0
>>> for i in range(len(a)):
...     for j in range(i + 1, len(a)):
...         if (a[i] + a[j]) % 2 == 0:
...             k += 1
...
>>> k
3

    break во вложенном цикле выходит только из внутреннего. В №26 (очередь к ячейкам) break после того, как пассажир занял ячейку, обязателен — иначе он займёт все свободные (Решу ЕГЭ 57433: 420 210 вместо 344 53).

    Подробнее: сколько ждать, когда перебор слишком велик

    Скорость. Простой цикл с одним-двумя if проходит примерно 10 млн шагов за секунду-другую (на слабом компьютере — в несколько раз медленнее). Перебор слов product + join — около 3 млн в секунду. Значит, 10⁷–10⁸ шагов — нормально, 10⁹ — уже минуты, а 10¹⁰ не дождаться. Нет ответа за 2–3 минуты — Ctrl+C и искать способ быстрее.

    Как сократить перебор.

    • Пары до 10⁵ × 10⁵ — перебирать одну переменную, вторую брать «самую опасную» (№15).
    • Квадраты и степени — перебирать корень или показатель, а не сами числа: «ровно 3 делителя» бывает только у p², и вместо чисел до 10⁹ хватит p до 31 623 (№25).
    • Кратные K — шагом: range(K, N + 1, K) в K раз короче (№25).
    • Огромный интервал (№16, 10⁹ чисел) — понять, что считает функция, проверить догадку перебором на малых числах и считать без перебора, например len(range(first, hi + 1, 10)).
    • То, что не меняется, — до цикла: min(a) внутри цикла по a пересчитывается на каждом шаге — на 10⁵ числах это в сотни раз дольше (№17).

    «Больше всего по всем x» — два прохода. В одном проходе максимум ещё неизвестен: сначала m = max(…) по всем x, потом второй цикл — первое (или последнее) x, у которого значение равно m (№14).

    Проходы «с запасом». Если алгоритм повторяет проходы, пока результат улучшается (№23, кратчайшие пути), меньше проходов — ошибки нет, а ответ хуже верного. Повторять, пока что-то меняется: флаг izmen = True и while izmen:.

    Типичные ошибки¶

    Скрытые ловушки — проверены запуском

    • Конец range не входит. «От 1 до N» — range(1, N + 1); «не превышающее 2030» — range(1, 2031) (№14).
    • Ответ равен границе range — граница мала: «наибольшее» молча печатает её (№11: 9999 вместо 32 768), «наименьшее» не печатает ничего. Расширить и проверить снова (№11, №15).
    • Натуральные — с 1, не с 0 (№5: 27 вместо 28); кратные K — range(K, N + 1, K), не с 0 (№25).
    • Наименьшее R ≠ R при наименьшем N — собрать все R и взять min (№5: 115 вместо 100).
    • Пары соседних — range(len(a) - 1), тройки — range(len(a) - 2), иначе IndexError (№17).
    • «Больше X» — первым проверяется X + 1: n += 1 в начале тела (№25).
    • «Целое A» — перебор и с отрицательных (№15); «k-значное» у отрицательных — через abs (№17).
    • Номер среди подходящих — свой счётчик внутри if, не enumerate (№8).
    • break в очереди (№26) — после того, как место занято; во вложенном цикле break выходит только из внутреннего.
    • min(a) внутри цикла — пересчитывается на каждом шаге; считать до цикла (№17).
    • Огромный перебор (10⁹ и больше) не дождаться — Ctrl+C, сокращать перебор (№8, №16, №25).
    • Убывающая куча без верхней границы (№19–21) — перебор S «до 1000» может не дойти до ответа; при двух кучах начинать с нижней границы S из условия (КомпЕГЭ 31227: 54 вместо 38).

    Где встречается¶
