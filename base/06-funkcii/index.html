    6. Функции и рекурсия¶

    Коротко

    def f(x): … return ответ — своя функция; return сразу заканчивает её и отдаёт значение (print только печатает). Рекурсия — функция вызывает сама себя: сначала условия остановки (if x > y: return 0), потом формула. Глубина — до ≈ 1000 вызовов, с @lru_cache(None) — до ≈ 500, дальше RecursionError. Кэш нужен, когда функция вызывает себя два раза и больше (№13, №16, №19–21, №23); большие n — прогрев циклом от базы вверх.

    Как пробовать примеры

    Строки с >>> набирайте в окне IDLE Shell и нажимайте Enter. Строки с ... — тело функции: набирайте с отступом, а в конце нажмите Enter ещё раз на пустой строке. Каждый пример на странице проверен запуском (Python 3.11 и 3.12).

    Своя функция: def и return¶

    Функция — кусок программы с именем: ей дают значения (параметры), она возвращает ответ. Записывается так: def, имя, параметры в скобках, двоеточие, тело с отступом. return — что вернуть:

    >>> def summa_cifr(n):
...     s = 0
...     while n > 0:
...         s += n % 10
...         n //= 10
...     return s
...
>>> summa_cifr(2027)
11
>>> summa_cifr(99) + summa_cifr(1)
19
>>> [x for x in range(10, 40) if summa_cifr(x) == 5]
[14, 23, 32]

    Функцию пишут, когда одно и то же действие нужно много раз: перевод в систему счисления (№5, №14), разложение на множители (№25), формула из условия (№16) — и тогда основной цикл короткий и читается как условие.

    return сразу выходит из функции — строки после него не выполняются. Поэтому после if … return не нужен else:

    >>> def znak(x):
...     if x > 0:
...         return 'плюс'
...     if x < 0:
...         return 'минус'
...     return 'ноль'
...
>>> znak(5), znak(-3), znak(0)
('плюс', 'минус', 'ноль')

    print ≠ return. print только показывает число на экране, а функция без return возвращает пустое None — с ним нельзя ни сложить, ни сравнить:

    >>> def dvazhdy(x):
...     print(x * 2)
...
>>> a = dvazhdy(5)
10
>>> print(a)
None
>>> a + 1
Traceback (most recent call last):
  ...
TypeError: unsupported operand type(s) for +: 'NoneType' and 'int'

    Несколько ответов — через запятую в return; получаются кортежем, его раскладывают по переменным:

    >>> def min_max(a):
...     return min(a), max(a)
...
>>> lo, hi = min_max([5, 8, 3])
>>> lo, hi
(3, 8)

    Переменные внутри функции — свои. Имя s, заведённое в функции, снаружи не видно и не портит переменную s основной программы. А вот прочитать внешнюю переменную функция может (так в №16 функции читают n из условия).

    lambda — короткая функция в одну строку без имени: lambda x: x % 10 — «по x вернуть последнюю цифру». Нужна в sorted(…, key=…), min(…, key=…) (§5).

    Рекурсия¶

    Рекурсия — функция, которая вызывает сама себя для меньшей (или более близкой к концу) задачи. Так записаны условия №16 («F(n) = F(n − 1) + n»), и так считают число программ в №13 и выигрыши в №19–21.

    Любая рекурсивная функция состоит из двух частей:

    1. условия остановки («база») — когда ответ известен сразу: n == 1, x == y, «куча ≥ 45»;
    2. шага — ответ через вызовы для других значений.

    Условия остановки — первыми: иначе функция будет вызывать себя бесконечно.

    >>> def F(n):
...     if n == 1:
...         return 1
...     return F(n - 1) + n
...
>>> F(1), F(2), F(3), F(100)
(1, 3, 6, 5050)

    F(3) вызывает F(2), та — F(1); F(1) отвечает сразу, и ответы возвращаются назад: 1 → 3 → 6.

    Число программ (№13). «Сколько программ из команд „прибавь 1“ и „умножь на 2“ переводят 1 в 10»: из числа x можно пойти любой командой — программ столько, сколько их у всех продолжений вместе:

    >>> def f(x, y):
...     if x > y:
...         return 0
...     if x == y:
...         return 1
...     return f(x + 1, y) + f(x * 2, y)
...
>>> f(1, 10)
14
>>> f(3, 12)
6

    x > y — «перелетели» (команды только увеличивают число), программа не годится — 0; x == y — пришли, нашлась одна программа. Порядок этих двух проверок не важен, важно, что они до вызовов.

    Глубина рекурсии¶

    Каждый вызов «ждёт» ответа следующего, и Python держит в памяти всю цепочку. Цепочка длиннее примерно 1000 вызовов — ошибка RecursionError. Обычно это значит, что условие остановки не срабатывает:

    >>> def f(x, y):
...     if x > y:
...         return 0
...     if x == y:
...         return 1
...     return f(x + 1, y) + f(x * 2, y)
...
>>> f(0, 10)
Traceback (most recent call last):
  ...
RecursionError: maximum recursion depth exceeded...

    Из нуля команда «умножь на 2» снова даёт 0 — число не растёт, и рекурсия идёт бесконечно. Так же бесконечны команды, которые у какого-то числа не меняют его: «прибавь предыдущее» у 1, «увеличь старшую цифру» у 9 (Решу ЕГЭ 9206). Если в условии старт — такое число, ответ «бесконечно много» или задачу надо читать внимательнее.

    Цепочка длинная по-честному — F(5000) при шаге 1 — тоже RecursionError. Тогда — прогрев (ниже) или цикл вместо рекурсии.

    lru_cache: запоминать ответы¶

    Когда функция вызывает себя два раза и больше, одни и те же значения считаются снова и снова, и время растёт как сам ответ (17 млн программ — 35 секунд). Посчитаем, сколько раз вызывается функция с F(n) = F(n − 1) + F(n − 2):

    >>> k = 0
>>> def F(n):
...     global k
...     k += 1
...     if n <= 2:
...         return 1
...     return F(n - 1) + F(n - 2)
...
>>> F(25), k
(75025, 150049)

    (global k — разрешить функции менять внешнюю переменную k; в решениях не нужно, здесь — только для подсчёта.) 150 тысяч вызовов ради 25 значений. @lru_cache(None) перед функцией запоминает ответ на каждое значение аргументов, и повторный вызов отвечает сразу:

    >>> from functools import lru_cache
>>> k = 0
>>> @lru_cache(None)
... def F(n):
...     global k
...     k += 1
...     if n <= 2:
...         return 1
...     return F(n - 1) + F(n - 2)
...
>>> F(25), k
(75025, 25)

    25 вызовов вместо 150 049. None — «запоминать без ограничения». Кэш ставят в №13 (если ответ — миллионы программ), №16, №19–21 (без кэша игра «без ограничения числа ходов» — 2¹⁰⁰ вызовов), №23 (число путей).

    • Две функции, которые вызывают друг друга (№16, F и G), — кэш у обеих.
    • Кэш помогает, только если аргументы повторяются: сумма пути в параметре функции (№23) делает почти все вызовы разными — кэш бесполезен.
    • Параметры функции с кэшем — числа, строки, кортежи; список — TypeError: unhashable type (§5).

    Большие n: прогрев вместо setrecursionlimit¶

    С кэшем цепочка вызовов становится вдвое короче допустимой: около 500 (Python 3.11 и 3.12). F(2026) без подготовки падает:

    >>> from functools import lru_cache
>>> @lru_cache(None)
... def F(n):
...     if n == 1:
...         return 1
...     return F(n - 1) + n
...
>>> F(2026)
Traceback (most recent call last):
  ...
RecursionError: maximum recursion depth exceeded...
>>> for i in range(1, 2027):
...     x = F(i)
...
>>> F(2026)
2053351

    Прогрев — вызвать функцию по порядку от базы вверх: каждое F(i) берёт из кэша готовое F(i − 1) и не уходит вглубь. Так написаны шаблоны №16 и №13 (там прогрев — от цели к началу). (x = F(i) — чтобы окно IDLE Shell не печатало 2026 чисел; в программе пишут просто F(i).)

    Почему не sys.setrecursionlimit. Совет «поднять предел» из разборов работает не везде: в Windows с lru_cache на Python 3.12 — снова RecursionError с глубины около 700, а Python 3.11 молча закрывается (ни ответа, ни сообщения об ошибке) с глубины около 1500 — на задачах Решу ЕГЭ это бывает. В Linux предел с кэшем выше (≈ 3300), но тоже есть. Прогрев работает везде.

    Кэш хранит всё. Если значения F — огромные числа (№16, «факториалы» ЕГЭ-2026), кэш на десятки тысяч значений занимает гигабайты (пересдача 2026, n = 42 038 — 1,5 ГБ; досрочная — оценка 13 ГБ). Тогда выражение сокращают вручную или считают циклом, который помнит только последние значения (карточка №16).

    Простые множители (№25)¶

    Функция, которую в №25 пишут почти всегда, — разложение на простые множители: делим на 2, 3, 4… пока делится, до корня из оставшегося числа:

    >>> def prostye(n):
...     p = []
...     i = 2
...     while i * i <= n:
...         while n % i == 0:
...             p.append(i)
...             n //= i
...         i += 1
...     if n > 1:
...         p.append(n)
...     return p
...
>>> prostye(12), prostye(49), prostye(13)
([2, 2, 3], [7, 7], [13])
>>> prostye(1103294351)
[163, 167, 40531]
>>> prostye(13) == [13]
True
    • if n > 1: p.append(n) после цикла — обязательно: остаток больше корня — тоже простой множитель. Без этой строки у 1103294351 = 163 · 167 · 40531 «останется два множителя», и число попадёт в ответ демоверсии-2027.
    • Простое число — prostye(n) == [n]; множители идут по возрастанию — наименьший p[0], наибольший p[-1].
    • «Наибольший простой делитель, не считая самого числа» — у простого n такого нет: p[-1] if len(p) > 1 else 0.
    • Через разложение быстрее, чем через все делители: для чисел около 10⁹ — секунды на пять ответов вместо 16 секунд на первый.
    Подробнее: теория игр (№19–21), «лучший путь» (№23), условие на последовательность команд

    Игра (№19–21) — функция f(s, m): «из позиции s тот, кто должен выиграть, выигрывает, если в игре осталось m ходов». Ходит победитель (m нечётное) — хватит одного выигрышного хода (any), соперник — победа должна быть при всех его ходах (all):

    >>> from functools import lru_cache
>>> @lru_cache(None)
... def f(s, m):
...     if s >= 45:
...         return m % 2 == 0
...     if m == 0:
...         return False
...     h = [f(s + 1, m - 1), f(s + 3, m - 1), f(s * 2, m - 1)]
...     return any(h) if m % 2 == 1 else all(h)
...
>>> [s for s in range(1, 45) if f(s, 2)]
[22]
>>> [s for s in range(1, 45) if f(s, 3) and not f(s, 1)]
[11, 19, 21]
>>> [s for s in range(1, 45) if f(s, 4) and not f(s, 2)]
[18, 20]
    • Конец игры проверяется до if m == 0: иначе победа последним ходом не засчитывается.
    • №20 — f(s, 3) and not f(s, 1), №21 — f(s, 4) and not f(s, 2): без not в списке лишние S, которые выигрывают раньше (Решу ЕГЭ: 28 из 80 и 24 из 81 ответов неверны).
    • №19 с «неудачным первым ходом Пети» — all меняют на any, но для №20/21 возвращают all.
    • Ход зависит от прошлых ходов («нельзя повторять ход соперника») — прошлый ход в параметры функции.
    • Подробно — карточка №19–21.

    «Лучший путь» рекурсией (№23). Тупик (дальше идти некуда, а до цели не дошли) возвращает 10**10 для наименьшего пути и -10**10 — для наибольшего, не 0: иначе тупик окажется «самым коротким путём» (решение сайта Решу ЕГЭ к демоверсии на демоверсии случайно верно, а на 6 из 9 задач КомпЕГЭ — нет).

    Условие на последовательность команд (№13) — «программа не содержит двух команд B подряд»: третий параметр — строка уже сделанных команд, проверка 'BB' in p вместо подсчёта:

    >>> def f(x, y, p):
...     if 'BB' in p or x > y:
...         return 0
...     if x == y:
...         return 1
...     return f(x + 1, y, p + 'A') + f(x * 2, y, p + 'B')
...
>>> f(1, 10, ''), f(1, 20, '')
(10, 37)

    «Вычти 1» среди увеличивающих команд (нет двух A подряд): отсечка — x > y + 1, а не x > y: из y + 1 ещё можно вернуться в y (Решу ЕГЭ 63039: 3 вместо 4).

    Типичные ошибки¶

    Скрытые ловушки — проверены запуском

    • Условие остановки после вызова (или забыто) — RecursionError; базу — первыми строками.
    • Команда не меняет число (x * 2 при x = 0, «прибавь предыдущее» у 1) — бесконечная рекурсия (№13).
    • print вместо return — функция возвращает None, дальше TypeError или неверное сравнение.
    • Нет кэша у ветвящейся рекурсии — время ≈ размер ответа, не дождаться (№13, №16, №23); две функции друг через друга — кэш у обеих (№16).
    • С lru_cache глубина ≈ 500, а не 1000: F(2026) без прогрева — RecursionError; реальная задача КомпЕГЭ 2530 проходит со старта 500 и падает со старта 504. Большие n — прогрев циклом от базы.
    • setrecursionlimit в Windows: 3.12 — снова RecursionError (≈ 700), 3.11 — молча закрывается (≈ 1500) (№16).
    • Кэш огромных чисел — гигабайты памяти (№16, «факториалы» 2026: до 13–20 ГБ) — сокращать вручную.
    • Разложение без if n > 1 — теряется последний большой множитель (№25, демо-2027).
    • Тупик = 0 в рекурсии «наименьший путь» — тупик становится «лучшим» (№23); 10**10.
    • Игра: конец игры — до m == 0; в №20/21 — not f(s, 1) / not f(s, 2) (№19–21).
    • Своя to_base без нуля — to_base(0, 3) возвращает пустую строку, цифра пропадает (№5) — §7.

    Где встречается¶

    №5 и №14 (своя функция перевода, §7), №13 (число программ, кэш, прогрев от цели), №16 (рекурсивные функции, кэш, прогрев, огромные числа), №19–21 (игра f(s, m)), №23 (число путей, «лучший путь»), №25 (разложение на множители).
