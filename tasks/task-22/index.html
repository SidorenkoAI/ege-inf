    №22. Параллельные процессы¶

    таблицы (LibreOffice Calc) можно Python ~7 мин 1 балл файл .ods

    Коротко

    Текст по столбцам по «;» → пустые клетки → 0 → строка «процесс 0» с концом 0. Столбец конец =МАКС(ВПР(C2;$A:$F;6;0);ВПР(D2;$A:$F;6;0);ВПР(E2;$A:$F;6;0))+B2, столбец начало =F2-B2+1, протянуть. Начало и конец — номера первой и последней миллисекунды, обе включительно. Ответ — одной формулой: МАКС, СЧЁТЕСЛИ, СЧЁТЕСЛИМН, НАИМЕНЬШИЙ. Если можно сдвигать процессы — диаграмма Ганта.

    Как узнать задачу¶

    • «В файле содержится информация о совокупности N вычислительных процессов, которые могут выполняться параллельно или последовательно… процесс B зависит от процесса A».
    • Таблица: ID процесса, время выполнения (мс), ID процессов, от которых он зависит, через «;» (0 — ни от кого). ID бывают не по порядку и не подряд (101, 102…; 10017…).
    • Вопрос — в конце, он и решает всё: минимальное время всех; сколько процессов идут на k-й мс; сколько завершены за первые T мс; за какое время завершатся k процессов; бывает «максимальная продолжительность отрезка, в течение которого возможно одновременное выполнение четырёх процессов» — это сдвиги.

    Смысл: процесс начинается сразу, как только завершились все процессы, от которых он зависит, — то есть после самого позднего из них. Поэтому «конец» = МАКС(концы поставщиков) + своё время.

    Шаблон¶

    Файл открывается в LibreOffice Calc. Данные — в A:C, первая строка — заголовки.

    Шаг Что сделать
    1 Выделить столбец C → Данные → Текст по столбцам, разделитель «точка с запятой» → ОК. Зависимости встанут по одной в клетку: C, D, E (у кого больше трёх — дальше, F…)
    2 Выделить клетки зависимостей (C2:E26) → Правка → Найти и заменить: найти ^$, заменить 0, в «Других параметрах» — флажки «Только выбранное» и «Регулярные выражения» → Заменить все. Пустые станут нулями
    3 Под таблицей строка процесса 0: в столбце A — 0, в столбце «конец» — 0. Числами, не формулой
    4 F2 «конец»: =МАКС(ВПР(C2;$A:$F;6;0);ВПР(D2;$A:$F;6;0);ВПР(E2;$A:$F;6;0))+B2 — по ID каждого поставщика ВПР находит его строку и берёт 6-й столбец (F — его конец); G2 «начало»: =F2-B2+1
    5 Выделить F2:G2 и протянуть до последнего процесса (двойной щелчок по маркеру) — но не на строку процесса 0
    6 Проверка на примере из условия: «процесс 3 начинается на 8-й мс, заканчивается на 9-й» — у вас должно получиться так же
    7 Ответ — формулой по вопросу (таблица ниже) в свободной клетке. Диапазоны — только строки процессов (F2:F26), без строки процесса 0
    В условии Формула (данные в строках 2–26)
    минимальное время, через которое завершится вся совокупность =МАКС(F2:F26)
    сколько процессов выполняются на k-й мс (параллельно, активны) =СЧЁТЕСЛИМН(G2:G26;"<="&7;F2:F26;">="&7) — начало ≤ k ≤ конец
    сколько могут быть завершены за первые T мс =СЧЁТЕСЛИ(F2:F26;"<="&17) — конец ≤ T
    за какое минимальное время завершатся k процессов =НАИМЕНЬШИЙ(F2:F26;14) — k-й по величине конец
    сколько начнутся не ранее k-й мс =СЧЁТЕСЛИ(G2:G26;">="&8)
    начнутся не ранее a-й и завершатся не позднее b-й мс =СЧЁТЕСЛИМН(G2:G26;">="&5;F2:F26;"<="&16)
    сумма ID: запустятся, но не успеют завершиться за первые T мс =СУММЕСЛИМН(A2:A26;G2:G26;"<="&41;F2:F26;">"&41)
    когда завершится процесс X =ВПР(X;$A:$F;6;0)
    сколько начнутся после завершения процесса X начало > конец X: =СЧЁТЕСЛИ(G2:G26;">"&18) (18 — конец X)
    «не ранее чем через 80 мс после запуска первого» это момент 80 — первая мс процесса 81-я или позже: ">="&81
    «в состоянии ожидания на 151-й мс» (ещё не начался) начало > 151: ">"&151

    Как считать миллисекунды

    Миллисекунды нумеруются с 1. Процесс без поставщиков длиной 4 мс идёт в 1-ю, 2-ю, 3-ю и 4-ю мс: начало 1, конец 4. Зависимый начинается в следующую мс после конца последнего поставщика. Поэтому начало = конец − время + 1, и «идёт в k-ю мс» — это начало ≤ k ≤ конец, оба знака нестрогие.

    LibreOffice и Excel

    LibreOffice Calc Excel
    текст по столбцам Данные → Текст по столбцам Данные → Текст по столбцам
    несколько условий СЧЁТЕСЛИМН, СУММЕСЛИМН то же
    пустая клетка в ВПР #Н/Д — поэтому нули не проверяли

    Аргументы разделяются ;. 4-й аргумент ВПР — всегда 0 (точное совпадение).

    Пример с разбором¶

    Задача (демоверсия ЕГЭ-2027, пересказ). В файле 25 процессов: ID, время (мс), ID процессов, от которых зависит (через «;», 0 — независимый). Определите максимальное количество процессов, которые параллельно выполняются на 7-й мс, если каждый процесс начинается в самое раннее допустимое время. Миллисекунды нумеруются с 1.

    Решение. Данные в A1:C26, у процессов до трёх поставщиков.

    Условие Что делаем
    зависимости через «;» C → Текст по столбцам → зависимости в C, D, E; пустые C2:E26 → 0
    «0» — независимый строка 27: A27 = 0, F27 = 0
    самое раннее время F2: =МАКС(ВПР(C2;$A:$F;6;0);ВПР(D2;$A:$F;6;0);ВПР(E2;$A:$F;6;0))+B2, G2: =F2-B2+1, протянуть до 26-й строки
    на 7-й мс =СЧЁТЕСЛИМН(G2:G26;"<="&7;F2:F26;">="&7)

    Процесс 1 (4 мс) ждёт процессы 3 (конец 9) и 25 (конец 5) — начало 10, конец 13. На 7-й мс идут 8 процессов. Ответ: 8.

    Проверка вторым способом

    Программа (ниже, «Подробнее: Python») даёт тот же ответ — 8. Её же ответы: все завершатся на 17-й мс; за первые 17 мс завершатся все 25.

    Разновидности¶

    Условие Как записать
    минимальное время всей совокупности (демо-2023, ЕГЭ-2023, ЕГКР 2025–2026, Крылов) =МАКС(F2:F26)
    на k-й мс (демо-2027, ЕГЭ-2025, ЕГЭ-2026 — 6-я и 26-я мс) СЧЁТЕСЛИМН: начало ≤ k, конец ≥ k
    завершены за первые T мс (демо-2026, ЕГЭ-2026 — 21 мс) СЧЁТЕСЛИ: конец ≤ T
    за какое время завершатся k процессов (ЕГЭ-2025) НАИМЕНЬШИЙ(конец;k) — или отсортировать концы
    начнутся не ранее a-й и завершатся не позднее b-й мс (пересдача ЕГЭ-2026) СЧЁТЕСЛИМН: начало ≥ a, конец ≤ b
    сумма ID «запустятся, но не завершатся» (СтатГрад) СУММЕСЛИМН: начало ≤ T, конец > T
    сколько процессов идут одновременно с процессом X начало ≤ конец X и конец ≥ начало X, минус сам X
    время одного процесса неизвестно — t; наибольшее t, при котором всё завершится за T мс (Крылов-2023) в клетку t пишем числа и смотрим МАКС — подбор (вкладка «Неизвестное и задержка»)
    процесс B может начаться не раньше чем через d мс после поставщика у процесса 0 конец −d, в формуле …)+d+B2 (вкладка «Неизвестное и задержка»)
    потеряна зависимость процесса X, общее время известно подставлять в клетку зависимости ID по очереди, пока МАКС не станет нужным; цикл (Err:522) — не подходит
    «отрезок, когда одновременно 4 (5) процессов», «максимального количества процессов» (демо 2024–2025, ЕГЭ-2024, апробации, Крылов) диаграмма Ганта и сдвиги — вкладка «Сдвиги»
    «время завершения каждого процесса минимально» / «начинается в самое раннее время» двигать нельзя — шаблон
    «время окончания всех процессов минимально» двигать можно, но общее время не увеличивать
    позже всех может начаться процесс; сколько начнутся не ранее k-й мс при минимальном общем времени сдвиги в пределах общего времени — вкладка «Сдвиги»
    одновременно не более K процессов (очередь) моделирование — вкладка «Не более K процессов»

    «Максимальная продолжительность отрезка, в течение которого возможно одновременное выполнение четырёх процессов». Здесь процессы можно начинать позже — и подобрать сдвиги так, чтобы четыре шли вместе как можно дольше. Помогает диаграмма Ганта в той же таблице — готовый файл с демоверсией ЕГЭ-2024: 22-gant.ods.

    Шаг Что сделать
    1 Шаблон, но перед «концом» — столбец «Сдвиг» (E, сначала везде 0): F2 =МАКС(ВПР(C2;$A:$F;6;0);ВПР(D2;$A:$F;6;0))+B2+E2
    2 В I1, J1, … — номера мс 1, 2, 3…; I2: =ЕСЛИ(И($G2<=I$1;$F2>=I$1);1;"") — протянуть вправо и вниз. Под таблицей — =СУММ(I2:I13): сколько процессов идут в эту мс
    3 Формат → Условное форматирование: клетки с 1 — заливка; в строке сумм — подсветка нужного числа
    4 Найти независимые группы (никто из одной группы не зависит от другой) и в каждой — самый длинный участок, где идут нужные 2 процесса
    5 Сдвигом первых процессов группы совместить эти участки. Пишите сдвиг в столбец E — зависимые процессы едут сами

    Демо ЕГЭ-2024 (12 процессов): группа 1–8 и группа 9–12. В группе 1–8 два процесса идут вместе дольше всего с 10-й по 16-ю мс (процесс 4 и процессы 5, 6) — 7 мс. В группе 9–12 две цепочки 9→11 и 10→12 идут вместе 13 мс подряд. Сдвиг 9 → процессам 9 и 10 (они начнутся на 10-й мс) — и с 10-й по 16-ю мс идут 4 процесса. Ответ: 7 (без сдвигов — 4; проверено в LibreOffice и перебором всех расстановок).

    • Двигать можно только позже; вместе с процессом едут все, кто от него зависит.
    • «Каждого минимально», «в самое раннее время» — не двигать: считать по диаграмме как есть.
    • «Всех минимально» — двигать, но конец всех — не позже МАКС без сдвигов.
    • «Максимального количества» — сначала найти, сколько процессов вообще могут идти вместе: максимум в каждой группе сложить.
    • Процесс, который ждёт двух поставщиков, разрывает участок: до него и после него — разные участки.

    «Одновременно может выполняться не более 3 процессов… из готовых запускается тот, у которого меньше ID. За какое время будут выполнены все процессы?» Формулой не посчитать — моделирование: в каждый момент закончившиеся освобождают места, на свободные места запускаются готовые (все поставщики завершены). Вручную — диаграммой Ганта, надёжнее программой (лист — в Блокнот, как в «Подробнее: Python»):

    # №22, свои данные (moi.txt): одновременно может выполняться не более 3 процессов; из готовых к запуску
# запускается процесс с наименьшим ID. За какое время будут выполнены все процессы?
# Ответ: 37
vremya, zavisit = {}, {}
for s in open('moi.txt', encoding='utf-8'):
    s = s.rstrip('\n').split('\t')
    if not s[0].isdigit():
        continue
    i = int(s[0])
    vremya[i] = int(s[1])
    zav = s[2] if len(s) > 2 else '0'
    zavisit[i] = [int(x) for x in zav.replace(',', ';').split(';') if x.strip() not in ('', '0')]

K = 3
konec = {}                                       # завершённые: ID → момент завершения
idet = {}                                        # идут сейчас: ID → момент, когда закончится
t = 0                                            # момент времени (мс от старта)
while len(konec) < len(vremya):
    for i in list(idet):                         # кто закончился ровно сейчас — освобождает место
        if idet[i] == t:
            konec[i] = t
            del idet[i]
    gotovy = sorted(i for i in vremya if i not in konec and i not in idet
                    and all(j in konec for j in zavisit[i]))   # все поставщики уже завершены
    for i in gotovy:                             # по возрастанию ID, пока есть свободные места
        if len(idet) < K:
            idet[i] = t + vremya[i]
    t += 1

print(max(konec.values()))

    Если в условии очередь («в момент готовности процесс ставится в очередь, запускается первый из очереди»), выбирать надо не наименьший ID, а того, кто дольше ждёт. На тех же данных — 38 вместо 37:

    # №22, свои данные (moi.txt): не более 3 процессов одновременно; готовый к запуску процесс ставится в очередь
# (готовые в один момент — по возрастанию ID), запускается первый из очереди. За какое время выполнятся все?
# Ответ: 38
vremya, zavisit = {}, {}
for s in open('moi.txt', encoding='utf-8'):
    s = s.rstrip('\n').split('\t')
    if not s[0].isdigit():
        continue
    i = int(s[0])
    vremya[i] = int(s[1])
    zav = s[2] if len(s) > 2 else '0'
    zavisit[i] = [int(x) for x in zav.replace(',', ';').split(';') if x.strip() not in ('', '0')]

K = 3
konec = {}                                       # завершённые: ID → момент завершения
idet = {}                                        # идут сейчас: ID → момент, когда закончится
ochered = []                                     # очередь готовых к запуску
t = 0                                            # момент времени (мс от старта)
while len(konec) < len(vremya):
    for i in list(idet):                         # кто закончился ровно сейчас — освобождает место
        if idet[i] == t:
            konec[i] = t
            del idet[i]
    ochered += sorted(i for i in vremya if i not in konec and i not in idet and i not in ochered
                      and all(j in konec for j in zavisit[i]))  # новые готовые — в конец очереди
    while ochered and len(idet) < K:             # запускаем первых из очереди, пока есть места
        i = ochered.pop(0)
        idet[i] = t + vremya[i]
    t += 1

print(max(konec.values()))

    Бывает «задача требует n процессов»: задача стартует, только если помещаются все её процессы; не помещается — может стартовать следующая по ID, которой места хватает (так получаются ответы Решу ЕГЭ).

    Неизвестное время t. «Определите максимально возможное целочисленное t, при котором вся совокупность завершится не более чем за 16 мс». Буква t ломает формулы — в её клетку пишем число и смотрим =МАКС(F2:F13): t = 0, 1, 2, … Ответ — последнее t, при котором МАКС ≤ 16 (от t итог только растёт).

    Задержка. «Процесс B может начать выполнение не раньше чем через 3 мс после завершения процесса A». В формулу конца — +3: =МАКС(ВПР(…);…)+3+B2, а у процесса 0 конец −3 — тогда у независимых задержки не будет.

    Потерянная зависимость. «Известно, что вся совокупность завершилась за 25 мс; определите ID процесса, после которого начался процесс 12». В клетку зависимости процесса 12 по очереди пишем ID и смотрим МАКС; Err:522 (циклическая ссылка) — такой ID не подходит.

    # №22, демоверсия ЕГЭ-2027 (лист скопирован в 22.txt): сколько процессов выполняются на 7-й мс,
# если каждый начинается в самое раннее допустимое время (миллисекунды нумеруются с 1).
# Ответ: 8
vremya, zavisit = {}, {}
for s in open('22.txt', encoding='utf-8'):
    s = s.rstrip('\n').split('\t')               # клетки строки разделены табуляцией
    if not s[0].isdigit():                       # строка заголовка
        continue
    i = int(s[0])
    vremya[i] = int(s[1])
    zav = s[2] if len(s) > 2 else '0'
    zavisit[i] = [int(x) for x in zav.replace(',', ';').split(';')   # разделитель «;» (бывает «,»)
                  if x.strip() not in ('', '0')]                    # «0» и пустое — ни от кого

konec = {i: 0 for i in vremya}                   # последняя мс процесса
for povtor in range(len(vremya)):                # как в №23: повторить столько раз, сколько процессов
    for i in vremya:
        konec[i] = max([konec[j] for j in zavisit[i]], default=0) + vremya[i]
nachalo = {i: konec[i] - vremya[i] + 1 for i in vremya}   # первая мс процесса

print(sum(1 for i in vremya if nachalo[i] <= 7 <= konec[i]))
    • Конец считается, как в таблице: МАКС(концы поставщиков) + время. Но процессы в файле идут вперемешку: когда считаем процесс 1, конец его поставщика 25 может быть ещё не найден. Поэтому, как в №23, повторяем столько раз, сколько процессов — каждый проход достраивает цепочки хотя бы на один процесс.
    • max([…], default=0) — у независимого процесса список поставщиков пуст, конец = время.
    • if x.strip() not in ('', '0') — пропускает «0», пустые клетки и пробелы («109; 112»).

    Все остальные вопросы — та же программа, другая последняя строка (свои данные, 18 процессов):

    # №22, свои данные (moi.txt, 18 процессов): все разновидности вопроса «без сдвигов» — одна программа,
# меняется только последняя строка. Каждый процесс начинается в самое раннее время, мс нумеруются с 1.
# Ответ: 26
# Ответ: 6
# Ответ: 9
# Ответ: 14
# Ответ: 8
# Ответ: 6
# Ответ: 22
# Ответ: 9
# Ответ: 4

for s in open('moi.txt', encoding='utf-8'):

konec = {i: 0 for i in vremya}
for povtor in range(len(vremya)):
    for i in vremya:
        konec[i] = max([konec[j] for j in zavisit[i]], default=0) + vremya[i]
nachalo = {i: konec[i] - vremya[i] + 1 for i in vremya}
P = vremya                                                          # все ID

print(max(konec.values()))                                          # все завершатся
print(sum(1 for i in P if nachalo[i] <= 9 <= konec[i]))             # идут в 9-ю мс
print(sum(1 for i in P if konec[i] <= 12))                          # завершены за первые 12 мс

print(sum(1 for i in P if nachalo[i] >= 4 and konec[i] <= 15))      # начнутся не ранее 4-й и завершатся не позднее 15-й
print(sum(i for i in P if nachalo[i] <= 12 < konec[i]))             # сумма ID: запустятся, но не завершатся за 12 мс
print(konec[16])                                                    # когда завершится процесс 16

    Типичные ошибки¶

    Скрытые ловушки — проверены в LibreOffice 26.8

    • Без строки процесса 0 или с пустыми клетками зависимостей ВПР даёт #Н/Д — в демо все 25 концов с ошибкой. Нужны и нули, и строка 0.
    • Строку процесса 0 протянули формулами — она ищет сама себя: циклическая ссылка Err:522 во всех строках. У процесса 0 — просто числа 0.
    • Строка процесса 0 в диапазоне ответа: =СЧЁТЕСЛИ(F:F;"<="&17) на демо — 26 вместо 25 (её конец 0 тоже «≤ 17»). Диапазон — только строки процессов.
    • ID записаны текстом (бывает в файлах — числа прижаты влево): ВПР числа по ним даёт #Н/Д, а СУММ и МАКС по такому столбцу — 0. Лечение — «Текст по столбцам» по столбцам A и B (Решу ЕГЭ 89205).
    • После «Найти и заменить» нули в пустых клетках — текстовые, но ВПР их находит (демо — 8, ошибок нет): второй раз заменять не нужно.
    • «Пробел после ;» («109; 112») «Текст по столбцам» превращает в число — ничего делать не надо.
    • Граница на единицу: «на 14-й мс» — начало ≤ 14 ≤ конец с началом = первой мс. Если «начало» — МАКС(концов поставщиков) (момент, после которого процесс стартует), то условие начало < 14. Перепутаешь — 2 вместо 3 (Решу ЕГЭ 81488). Проверяйте на примере из условия: процесс 3 — с 8-й по 9-ю мс.
    • «Через 80 мс после запуска» — это момент 80, первая мс процесса — 81-я или позже; «не ранее 8-й мс» — первая мс 8-я или позже. Разница в единицу.
    • «За первые 17 мс» — конец ≤ 17 (успел и тот, кто закончил на 17-й); «не успеют завершиться» — конец > T.
    • Минимум, а считаем МАКС: «минимальное время всех» — когда завершится последний, то есть максимум концов.
    • МАКС, а не сумма концов поставщиков: процесс ждёт самого позднего, а не всех по очереди.
    • Сдвиги: «каждого минимально» и «всех минимально» — разные задачи (без сдвигов демо ЕГЭ-2024 дало бы 4 вместо 7, Решу 76125 — 10 вместо 4). И наоборот: «при минимальном общем времени» сколько процессов могут начаться не ранее 15-й мс — с учётом сдвигов 8, по самому раннему началу 7 (ЕГЭ-2026, Решу 92199).
    • Очередь ≠ наименьший ID: по «очереди готовых» и по «наименьшему ID» ответы разные (свои данные: 38 и 37). На Решу ЕГЭ 75286 ответ сайта 42 посчитан по наименьшему ID, а в условии — очередь: верно 40.
    • ВПР без 0 в конце или без $ в диапазоне — ищет не то или «уезжает» при протягивании.
