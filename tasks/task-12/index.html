    №12. Машина Тьюринга (исполнитель МТ)¶

    Python можно вручную ~6 мин 1 балл без файла

    Коротко

    Таблицу программы — в словарь prog (клетки как в условии, пустой символ λ пишем _), ленту — в список с запасом _ по краям; цикл: взять команду → записать символ → S — стоп, L/R — сдвиг. «Результат работы» — один прогон; «какое исходное число» — перебор чисел; «лента неизвестна, наибольшее/наименьшее» — понять, что делает программа, и перебрать строение ленты.

    Как узнать задачу¶

    • «Исполнитель МТ представляет собой читающую и записывающую головку…» — почти две страницы описания, таблица программы со столбцами λ, 0, 1 и строками q0, q1, …
    • Всё, что меняется от варианта к варианту, — после слов «Выполните задание»: что записано на ленте (двоичная запись числа или «последовательность из 1000 символов»), где головка, таблица и вопрос. Описание до этих слов одинаковое — его достаточно понять один раз.
    • Команда в клетке — «что записать, куда сдвинуться, новое состояние»: L — влево, R — вправо, N — остаться на месте, S — остановиться (символ при этом записывается). Начинает головка всегда в состоянии q0.

    До 2026 года №12 был «Исполнитель Редактор» (команды «заменить» и «нашлось») — его разборы сюда не подходят.

    Шаблон¶

    # №12: на ленте — двоичная запись числа 2030, головка в ближайшей клетке справа от неё.
# Программа идёт влево, меняет 0 ↔ 1, на пустой клетке слева пишет 1 и останавливается. Число на ленте после работы?
# Ответ: 2065
prog = {                                       # таблица: состояние → {символ: 'запись, сдвиг, новое состояние'}
    'q0': {'_': '_, L, q1'},                   # пустой символ λ пишем как '_'
    'q1': {'_': '1, S, q1', '0': '1, L, q1', '1': '0, L, q1'},
}


def mt(s):                                     # s — что записано на ленте; вернёт ленту после работы
    lenta = ['_'] * 10 + list(s) + ['_'] * 10  # пустые клетки по краям — с запасом
    i = 10 + len(s)                            # головка: ближайшая клетка справа (слева — i = 9)
    q = 'q0'
    while True:
        z, d, q = prog[q][lenta[i]].split(', ')   # команда на пересечении состояния и символа
        lenta[i] = z                           # сначала записать символ
        if d == 'S':                           # S — стоп (символ уже записан)
            break
        if d == 'L':
            i -= 1
        if d == 'R':
            i += 1                             # N — головка остаётся на месте
    return ''.join(lenta).strip('_')           # лента без пустых клеток по краям


print(int(mt(bin(2030)[2:]), 2))

    Что менять под задачу:

    В условии В шаблоне
    таблица программы prog: строка таблицы — 'q1': {…}, клетка — 'символ': 'запись, сдвиг, состояние' как в условии, λ → _; пустые клетки таблицы не пишем
    «двоичная запись числа 2025 без ведущих нулей» bin(2025)[2:] — [2:] убирает 0b
    «300 единиц, затем 200 двоек, затем …» '1' * 300 + '2' * 200 + … (вкладка «Лента из блоков»)
    головка «в ближайшей ячейке справа от последовательности» i = 10 + len(s)
    головка «в ближайшей ячейке слева» i = 9; на первом символе — i = 10, на последнем — i = 9 + len(s)
    «запишите число в десятичной системе» int(mt(s), 2)
    «сколько нулей», «сумма цифр» mt(s).count('0'), sum(map(int, mt(s)))
    «какое наименьшее (наибольшее) число было на ленте» перебор исходных чисел (вкладка «Перебор чисел»)
    «1000 символов в неизвестном порядке, … наибольшее возможное» перебор строения ленты (вкладка «Лента неизвестна»)

    Пример с разбором¶

    Задача (демоверсия ЕГЭ-2027, пересказ). На ленте — двоичная запись числа 2025 без ведущих нулей, по краям пустые клетки λ, головка — в ближайшей клетке справа от записи, состояние q0. Программа:

    λ 0 1
    q0 λ, L, q1
    q1 1, L, q2 0, L, q1 1, L, q1
    q2 λ, S, q2

    Определите результат работы программы — число на ленте в десятичной системе.

    Решение. Переписываем таблицу и данные в шаблон:

    Условие Код
    строка q1: на λ — 1, L, q2, на 0 — 0, L, q1, на 1 — 1, L, q1 'q1': {'_': '1, L, q2', '0': '0, L, q1', '1': '1, L, q1'}
    на ленте — двоичная запись 2025 mt(bin(2025)[2:])
    головка справа от записи i = 10 + len(s)
    ответ — в десятичной системе int(…, 2) 
    # №12, демоверсия ЕГЭ-2027: на ленте — двоичная запись числа 2025, головка в ближайшей клетке справа.
# Определите результат работы программы — число на ленте в десятичной системе.
# Ответ: 111111101001
# Ответ: 4073
prog = {
    'q0': {'_': '_, L, q1'},
    'q1': {'_': '1, L, q2', '0': '0, L, q1', '1': '1, L, q1'},
    'q2': {'_': '_, S, q2'},
}


def mt(s):
    lenta = ['_'] * 10 + list(s) + ['_'] * 10
    i = 10 + len(s)                            # головка справа от записи
    q = 'q0'
    while True:
        z, d, q = prog[q][lenta[i]].split(', ')
        lenta[i] = z
        if d == 'S':
            break
        if d == 'L':
            i -= 1
        if d == 'R':
            i += 1
    return ''.join(lenta).strip('_')


print(mt(bin(2025)[2:]))                       # 111111101001 — слева приписана единица
print(int(mt(bin(2025)[2:]), 2))

    Ответ: 4073.

    Проверка вручную: что делает каждое состояние

    q0 — один шаг с пустой клетки влево, на последнюю цифру. q1 едет влево по цифрам и ничего не меняет (0 → 0, 1 → 1), а на пустой клетке слева пишет 1 и переходит в q2. q2 сразу останавливается. Значит, программа приписывает слева единицу: в записи 2025 одиннадцать цифр, и число становится 2025 + 2¹¹ = 2025 + 2048 = 4073. Так — «словами по строкам таблицы» — решают вручную; программа — проверка (и выручает, когда таблица большая).

    Разновидности¶

    Условие Как записать
    «определите результат работы программы», на ленте двоичная запись числа (демо-2027, ЕГЭ-2026, ЕГКР, апробация) шаблон: int(mt(bin(N)[2:]), 2)
    программа дописывает цифры справа / слева, меняет одну цифру, прибавляет 1, идёт «туда и обратно» шаблон — таблица сама всё сделает; запас пустых клеток 10 (см. «Типичные ошибки»)
    лента «блоками»: 323 двойки, затем 115 нулей, затем 562 единицы; вопрос — сумма или количество цифр лента из блоков + sum/count (вкладка)
    «в произвольном порядке», но количества цифр известны и в вопросе нет «наибольшее/наименьшее» ответ от порядка не зависит — собрать ленту в любом порядке (проверка — переставить блоки)
    «наименьшее число, которое могло быть на ленте, если получилось 240» перебор исходных чисел (вкладка); у исходного числа нет ведущих нулей, у результата — могут быть
    «наибольшее число, не превышающее 903, которое может получиться» тот же перебор: max из результатов ≤ 903
    «1000 символов (0 и 1), после работы осталось 343 нуля — наибольшее (наименьшее) число нулей (единиц) в исходной» понять, где программа останавливается, и перебрать строение ленты (вкладка «Лента неизвестна»)
    «сколько различных значений может принимать число нулей», «наибольшее число заменённых символов» то же; закономерность (N − K + 1) видна на уменьшенной копии
    программа проходит всю ленту без остановки, цифры меняются по кругу (0 → 1 → 2 → 0, 3 ↔ 0, 5 и 7 → 1) + условие на количества или сумму после работы перебор количеств цифр (вкладка «Перебор количеств»)
    «после работы все соседние символы различны» (СтатГрад) на ленте чередование 1010…; при нечётной длине — два варианта, взять лучший
    «S — сумма цифр после работы, шестизначная; наименьшее S + N» перебор количеств цифр с запасом
    «каждая вторая единица становится нулём» (пара состояний q2 ⇄ q3) шаблон; вручную — 103 единицы → 51 нуль (103 // 2)
    команда N (без сдвига): в одной клетке 2 → 1 → 3 шаблон: сдвига нет — следующая команда в той же клетке
    программа пишет λ (стирает символы) шаблон; лента становится короче — считать по mt(s)
    алфавит не 0 и 1 (2, 3, 7; 4, 6, 8; 5, 7, 9; 1, 3, 4) шаблон: ключи словаря — эти символы
    головка «на неизвестном расстоянии справа» q0 идёт по пустым клеткам: i = 10 + len(s) + 3 — расстояние не важно 
    # №12: на ленте — двоичная запись натурального числа без ведущих нулей, головка справа от неё.
# Программа меняет каждую цифру на противоположную. После работы на ленте — двоичная запись числа 100.
# Какое наименьшее число могло быть записано на ленте?
# Ответ: 155
prog = {
    'q0': {'_': '_, L, q1'},
    'q1': {'_': '_, S, q1', '0': '1, L, q1', '1': '0, L, q1'},
}


def mt(s):
    lenta = ['_'] * 10 + list(s) + ['_'] * 10
    i = 10 + len(s)
    q = 'q0'
    while True:
        z, d, q = prog[q][lenta[i]].split(', ')
        lenta[i] = z
        if d == 'S':
            break
        if d == 'L':
            i -= 1
        if d == 'R':
            i += 1
    return ''.join(lenta).strip('_')


for n in range(1, 10000):                      # перебираем исходные числа по возрастанию
    if int(mt(bin(n)[2:]), 2) == 100:
        print(n)                               # первое найденное — наименьшее
        break

    Инверсия 100 = 1100100₂ — это 0011011, но с нуля запись числа начинаться не может. Значит, слева была ещё единица (после работы она стала незначащим нулём): 10011011₂ = 155, а не 27. Перебор это учитывает сам.

    Все 2¹⁰⁰⁰ лент не перебрать. Сначала понимаем, где программа останавливается и что остаётся нетронутым, потом перебираем строение ленты — несколько чисел, а не символы:

    # №12, демоверсия ЕГЭ-2026: 1000 символов (0 и 1), головка справа; программа идёт влево, каждый 0 меняет на 1,
# на первой единице пишет 0 и останавливается. Осталось ровно 343 нуля. Наибольшее число нулей в исходной ленте?
# Лента = «левая часть» + 1 + j нулей: левая часть не меняется, единица станет нулём, j нулей — единицами.
# Ответ: 999
N, K = 1000, 343                               # длина ленты; нулей после работы
best = 0
for j in range(N):                             # j нулей справа от самой правой единицы
    for z in range(N - j):                     # z нулей в левой части (остальное в ней — единицы)
        if z + 1 == K:                         # нулей после работы: z и бывшая единица
            best = max(best, z + j)            # нулей до работы
print(best)                                    # лента без единиц не подходит: все нули станут единицами

    Проверка — уменьшенная копия: та же программа на всех лентах длины 6–10 и «осталось k нулей». Шаблон здесь работает целиком, а закономерность видна по выводу (здесь — всегда n − 1):

    # №12, демоверсия ЕГЭ-2026: на ленте 1000 символов (только 0 и 1), головка в ближайшей клетке справа.
# После работы программы на ленте осталось ровно 343 нуля. Наибольшее возможное число нулей в исходной ленте?
# Все 2^1000 лент не перебрать — решаем «уменьшенную копию»: все ленты длины n, «осталось k нулей».
# Ответ: 6 2 5
# Ответ: 8 3 7
# Ответ: 10 4 9
# Ответ: 999
from itertools import product

prog = {
    'q0': {'_': '_, L, q1'},
    'q1': {'_': '_, S, q1', '0': '1, L, q1', '1': '0, S, q1'},
}


def mt(s):
    lenta = ['_'] * 10 + list(s) + ['_'] * 10
    i = 10 + len(s)
    q = 'q0'
    while True:
        z, d, q = prog[q][lenta[i]].split(', ')
        lenta[i] = z
        if d == 'S':
            break
        if d == 'L':
            i -= 1
        if d == 'R':
            i += 1
    return ''.join(lenta).strip('_')


for n, k in (6, 2), (8, 3), (10, 4):           # маленькие длины и «осталось k нулей»
    best = 0
    for t in product('01', repeat=n):          # все ленты длины n
        s = ''.join(t)
        if mt(s).count('0') == k:
            best = max(best, s.count('0'))
    print(n, k, best)                          # каждый раз n - 1, от k не зависит
print(1000 - 1)

# а сумма всех цифр равна 500. Сколько единиц было на ленте до начала работы?
# Ответ: 201
# Ответ: 600

}


def mt(s):

print(mt('012'))                               # что делает программа: 0 → 2, 1 → 0, 2 → 1
for a in range(1001):                          # a нулей, b единиц, c двоек в исходной ленте
    for b in range(1001 - a):
        c = 1000 - a - b
        n0, n1, n2 = b, c, a                   # после работы: нули — из единиц, единицы — из двоек, двойки — из нулей

prog = {

    Подробнее: решение вручную

    Так решают большинство разборщиков — и демо, и задачи с неизвестной лентой.

    1. Где головка и что делает q0 — обычно один шаг с пустой клетки на запись.
    2. Словами по строкам таблицы: «q1: 0 → 1 и влево, 1 → 0 и стоп, λ — стоп». Если во всей строке одно и то же направление и одно состояние, головка просто едет в одну сторону.
    3. Где программа останавливается и что остаётся нетронутым (всё за точкой остановки).
    4. Если неясно — прогнать 3–5 символов на бумаге (или mt на коротких лентах).
    5. Для «наибольшего/наименьшего» — построить крайнюю ленту и пересчитать её: «342 нуля, 1, 657 нулей» → после работы 342 + 1 = 343 нуля, в исходной 999.

    Типичные ошибки¶

    Скрытые ловушки — проверены запуском

    • Мало пустых клеток слева — ошибки нет, ответ неверный. Если головка уходит левее начала списка, lenta[-1] в Python — это последняя клетка ленты: программа молча пишет в другой конец. Задача «приписать 10 слева к 2028» с одной пустой клеткой слева даёт 4057 вместо 6124 (Python 3.11 и 3.12). Справа нехватка даёт IndexError. Запас — 10 клеток с каждой стороны.
    • Остановка раньше записи. S — «записать и остановиться». Если проверить d == 'S' до lenta[i] = z, последний символ потеряется: в шаблоне 17 вместо 2065.
    • int пропускает подчёркивание. int('1_0', 2) = 2: Python разрешает _ между цифрами. Если программа стирает символы (пишет λ) посреди записи, int молча склеит куски. По краям _ убирает strip('_').
    • Ведущие нули. Число на ленте до работы — без ведущих нулей, а после работы они могут быть. «Получилось 240, какое наименьшее было?» — 271, а не 15 (у Крылова и в разборах; так же 88 → 167, 100 → 155).
    • «Как в демо» — не всегда. Головка слева, на первом нуле стоп (600 символов, осталось 250 нулей, наименьшее число единиц): ответ 349, а не 599 по аналогии. Каждый раз смотрите, где остановка.
    • ±1 от остановки. Символ, на котором программа остановилась, тоже изменился: 343 нуля после работы — это 342 нетронутых и бывшая единица; «осталось 45 единиц» — одна из них бывший ноль (887, а не 888).
    • Перепутали, где головка. Слева — i = 9, справа — i = 10 + len(s). Начали на цифре вместо пустой клетки — в prog['q0'] нет такого символа: KeyError.
    • bin(n) без [2:] — на ленту попадают 0 и b: KeyError.
    • Опечатка при переписывании таблицы — самая частая ошибка программой. Сверьте словарь с таблицей построчно, и проверьте одну-две строки «словами».
    • Лента строкой, а не списком. Строку менять нельзя: s[i] = '1' — TypeError. Поэтому list(s).
    • «Наибольшее возможное» при единственном ответе. Если программа меняет каждый символ без остановки, ответ один: слово «наибольшее» — не подвох (инверсия, осталось 515 нулей → было 485).
    • Жадность в задачах на сумму. «Больше четвёрок — больше сумма» неверно: 799 цифр 1/3/4, сумма после 900 — максимум 2497 при 100 четвёрках. Перебирайте количества, а не угадывайте.
