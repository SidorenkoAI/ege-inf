    №25. Маски чисел, делители, простые множители¶

    Python ~20 мин 1 балл без файла

    Коротко

    Сначала понять, что спрашивают: от этого зависит шаблон.

    • А. Маска («соответствуют маске 3?12?14*5 и делятся на 1917»): перебирать только кратные — for x in range(K, N + 1, K), проверка fnmatch(str(x), маска), вывод print(x, x // K).
    • Б. Делители и простые множители («сумма наименьшего и наибольшего делителей», «произведение ровно двух простых множителей»): две функции — deliteli(n) (все делители, до корня парами) и prostye(n) (простые множители с повторами). Дальше — условие задачи дословно, while count < 5: n += 1.

    Как узнать задачу¶

    • «Назовём маской числа последовательность цифр… символ «?» означает ровно одну цифру, «*» — любую последовательность цифр»: это шаблон А.
    • «Напишите программу, которая перебирает целые числа, большие 800 000, и ищет среди них такие, у которых… делитель…», «простых множителей», «первые пять найденных чисел»: шаблон Б.
    • Файла нет, ответ — таблица: в первом столбце числа, во втором — частное, делитель, множитель или значение M. Строк в бланке «избыточно»: записывайте столько, сколько вывела программа.

    В демоверсии 2027 даны оба вида (на экзамене будет один):

    Вид Как звучит Шаблон
    маска + делимость «не превышающих 10¹⁰, соответствуют маске 3?12?14*5, делятся на 1917» А
    делители «M — сумма наименьшего и наибольшего делителей, не считая 1 и самого числа», «есть делитель, оканчивающийся на 7» Б, deliteli
    простые множители «произведение ровно двух простых множителей, не обязательно различных, каждый содержит 16 ровно один раз» Б, prostye

    Шаблон¶

    А. Маска¶

    # №25, демоверсия ЕГЭ-2027 (пример 2): числа не больше 10^10 по маске 3?12?14*5, делящиеся на 1917; вывести число и частное
# Ответ: 351261495 183235
# Ответ: 3212614035 1675855
# Ответ: 3412614645 1780185
# Ответ: 3712414275 1936575
# Ответ: 3912414885 2040905
from fnmatch import fnmatch

K = 1917
for x in range(K, 10**10 + 1, K):      # только кратные K: K, 2K, 3K, …
    if fnmatch(str(x), '3?12?14*5'):   # «?» — одна цифра, «*» — любые цифры, в том числе ни одной
        print(x, x // K)

    Как это работает. Все числа до 10¹⁰ перебирать нельзя: это 10 миллиардов проверок. Нужные числа делятся на K, поэтому идём шагом K, начиная с K: K, 2K, 3K… — это 5 миллионов чисел, около 5 секунд. fnmatch сравнивает строку с маской: ? — ровно один символ, * — любые символы, в том числе ни одного. Маска в условии и в fnmatch записывается одинаково, переписывайте её посимвольно.

    В условии В шаблоне
    «не превышающих 10¹⁰» граница 10**10 + 1 (range не включает правый край)
    «делятся на 1917» K = 1917, range(K, …, K); начинать с K, а не с 0 (0 — не натуральное)
    «во втором столбце — результат деления» print(x, x // K) — именно //, иначе выйдет 183235.0
    «в ответе запишите все найденные числа» print(x)
    «?» — чётная цифра («нечётная») в маске [02468] ([13579]) — одна цифра из перечисленных
    «делятся на 31 и на 2031» шаг — наименьшее общее кратное: 31 * 2031 (общих делителей нет); для 4 и 6 — 12, а не 24
    дополнительно «ровно три делителя», «простые», «полный квадрат» ещё одно условие в if: len(deliteli(x)) == 3, == 2, isqrt(x) ** 2 == x
    делимости нет («простые числа по маске 3?1111*») range(1, N + 1), но сначала маска, потом простота: маска быстрее
    K маленький (13, 23), а граница 10¹⁰ кратных — сотни миллионов, fnmatch не дождаться: «Подробнее: перебор чисел маски»

    Б. Делители и простые множители¶

    # №25, своя задача: M — сумма наименьшего и наибольшего делителей числа, не считая 1 и самого числа (нет таких — M = 0).
# Первые 5 чисел больше 654 321, у которых M оканчивается на 6; вывести число и M
# Ответ: 654328 327166
# Ответ: 654329 50346
# Ответ: 654339 218116
# Ответ: 654348 327176
# Ответ: 654353 93486
from math import isqrt


def deliteli(n):                 # все делители n по возрастанию
    d = set()
    for i in range(1, isqrt(n) + 1):
        if n % i == 0:           # нашли делитель i — у него есть пара n // i
            d.add(i)
            d.add(n // i)
    return sorted(d)


count = 0
n = 654321
while count < 5:
    n += 1
    d = deliteli(n)[1:-1]        # без 1 и самого числа
    M = d[0] + d[-1] if d else 0
    if M % 10 == 6:
        print(n, M)
        count += 1

    Как это работает. Делители идут парами: нашли делитель i — второй в паре n // i. Меньший в паре не больше корня, поэтому i перебираем до isqrt(n) (целая часть корня) включительно. Пары складываем в множество: у квадрата i == n // i, и в списке корень оказался бы дважды. sorted даёт список по возрастанию: d[0] — наименьший, d[-1] — наибольший.

    Если в условии слово «простые» (простые множители, простые делители), нужна вторая функция:

    # №25, демоверсия ЕГЭ-2027 (пример 1): первые 5 чисел больше 1 103 285 717 — произведения ровно двух простых
# множителей, каждый из которых ровно один раз содержит «16»; вывести число и наименьший множитель
# Ответ: 1103299319 1693
# Ответ: 1103309477 1693
# Ответ: 1103322107 16187
# Ответ: 1103323021 1693
# Ответ: 1103328547 3169
def prostye(n):                  # простые множители n с повторами: 12 → [2, 2, 3]
    p = []
    i = 2
    while i * i <= n:
        while n % i == 0:        # пока делится — множитель i
            p.append(i)
            n //= i
        i += 1
    if n > 1:                    # остался последний большой простой множитель
        p.append(n)
    return p


count = 0
n = 1103285717
while count < 5:
    n += 1                       # «большие» — со следующего числа
    p = prostye(n)
    if len(p) == 2 and str(p[0]).count('16') == 1 and str(p[1]).count('16') == 1:
        print(n, p[0])           # множители идут по возрастанию: наименьший — p[0]
        count += 1

    prostye делит число на 2, 3, 4… пока делится, и записывает делитель. Составные (4, 6…) в список не попадут: их двойки и тройки уже «вынуты». Цикл идёт, пока i * i <= n, и n при этом уменьшается. Что осталось после цикла (если больше 1) — последний, самый большой простой множитель. Множители выходят по возрастанию и с повторами: prostye(12) = [2, 2, 3], prostye(13) = [13]. Для чисел около миллиарда это в разы быстрее, чем искать все делители и проверять каждый на простоту.

    Что менять под задачу:

    В условии В шаблоне
    «не считая единицы и самого числа» deliteli(n)[1:-1]
    «если таких делителей нет, M = 0» M = d[0] + d[-1] if d else 0 — у простого числа список пуст
    «M оканчивается на 4», «на 18» M % 10 == 4, M % 100 == 18
    «M при делении на 7 даёт остаток 3» M % 7 == 3
    «есть делитель, оканчивающийся на 7, не равный 7 и самому числу» d = [x for x in deliteli(n) if x % 10 == 7 and x != 7 and x != n], if d:, наименьший — d[0]
    R — «сумма всех делителей» / «не считая 1 и числа» sum(deliteli(n)) / sum(deliteli(n)[1:-1]) — читайте, что сказано
    «целая часть среднего арифметического» sum(d) // len(d) if d else 0
    «два наибольших», «пятый по величине», «5 наименьших» d[-1] + d[-2], d[-5], d[:5] (сначала проверить len(d))
    «ровно 4 делителя», «ровно 4 чётных» len(d) == 4; чётные — [x for x in deliteli(n) if x % 2 == 0]
    «простое число» len(deliteli(n)) == 2 или prostye(n) == [n]
    «ровно двух простых множителей, не обязательно различных» p = prostye(n), len(p) == 2 (с повторами: 49 = 7 · 7 подходит)
    «ровно трёх», «пяти» множителей len(p) == 3, len(p) == 5; «трёх различных» — ещё len(set(p)) == 3
    «каждый содержит 16 ровно один раз», «ровно одну цифру 5» all(str(q).count('16') == 1 for q in p); «хотя бы одну 2 или 3» — '2' in str(q) or '3' in str(q)
    «наибольший простой делитель, не считая самого числа» p = prostye(n), M = p[-1] if len(p) > 1 else 0 — у простого n единственный множитель — само n
    «сумма различных простых делителей» sum(set(p))
    «перебирает числа, большие 800 000» n = 800000, в цикле сначала n += 1 — первым проверяется 800 001
    «меньшие 800 000, в порядке убывания» n = 800000, n -= 1
    «на отрезке [a; b]» for n in range(a, b + 1):

    Пример с разбором¶

    Задача (демоверсия ЕГЭ-2027, пример 1). Перебирая целые числа, большие 1 103 285 717, найдите первые пять чисел, которые являются произведением ровно двух простых множителей, не обязательно различных, и каждый множитель ровно один раз содержит в записи 16. Для каждого запишите число и наименьший множитель.

    Решение — шаблон Б, prostye (программа — выше):

    Условие Код
    числа, большие 1 103 285 717 n = 1103285717, в цикле сначала n += 1
    первые пять count = 0, while count < 5:, при находке count += 1
    произведение ровно двух простых, «не обязательно различных» p = prostye(n), len(p) == 2 — повторы в списке остаются
    каждый содержит 16 ровно один раз str(p[0]).count('16') == 1 and str(p[1]).count('16') == 1 (не '16' in — это «хотя бы раз»)
    наименьший множитель p[0]: множители идут по возрастанию

    Программа печатает пять строк за 10–15 секунд — числа около миллиарда, подождать можно.

    Ответ:
    1103299319 1693
    1103309477 1693
    1103322107 16187
    1103323021 1693
    1103328547 3169

    Пример 2 демоверсии (маска 3?12?14*5, делятся на 1917, не больше 10¹⁰) — шаблон А, программа в начале «Шаблона»: 351261495 183235, 3212614035 1675855, 3412614645 1780185, 3712414275 1936575, 3912414885 2040905.

    Проверка вручную

    1103299319 = 1693 · 651683: 1693 и 651683 — простые (проверьте len(deliteli(…)) == 2), «16» в каждом ровно один раз. Для маски: 351261495 = 351261495 — ? = 5, ? = 6, * = «9», последняя 5; 351261495 / 1917 = 183235 без остатка.

    Разновидности¶

    В условии Как записать
    маска, делится на K, «не превышающих 10⁸…10¹²» (ЕГЭ 2022–2023, демо 2023–2027, Крылов-2026 в9–в16) шаблон А
    «?» — чётная / нечётная цифра (СтатГрад 2025) [02468], [13579] — вкладка «Чётная цифра»
    маска + «делится на 31 и на 2031» + «количество делителей — степень двойки» (ЕГЭ 2023) шаг 31 * 2031; len(deliteli(x)) in [2 ** i for i in range(40)]
    маска + «ровно три делителя» на отрезке [10⁸; 2 · 10⁸] три делителя — только у p², перебираем p — вкладка «Ровно три делителя»
    маска + «простые» (без делимости), маска + «полный квадрат» range(1, N + 1), сначала маска; isqrt(x) ** 2 == x
    маска, а кратных сотни миллионов (K = 13…50 при 10¹⁰, граница 10¹²) «Подробнее: перебор чисел маски»
    отрезок, «ровно 4 делителя» / «ровно 2 делителя, не считая 1 и числа» / «ровно 4 чётных» — вывести их (демо 2021) d = deliteli(n), len(d) == 4, print(*d) — вкладка «Ровно k делителей»
    отрезок, число с наибольшим количеством делителей, из равных — наименьшее c > best (строго): при равенстве остаётся первое
    простые числа отрезка с номером k += 1, print(k, n)
    M = min + max (или max − min) делителей без 1 и числа, «оканчивается на 4», «M mod 7 = 3» (демо 2022, 2025, 2026, ЕГЭ 2024, Крылов) шаблон Б, как в программе выше
    есть делитель, оканчивающийся на 7 (8, 9, 11), не равный ему и числу; наименьший такой (ЕГЭ 2021, 2024, досрок 2025, 2026) вкладка «Делитель на 7»
    R — сумма делителей, F — среднее, S = min² + max² простое, произведение 5 наименьших, два наибольших, пятый по величине таблица «Что менять» выше
    наибольший простой делитель ≤ 15 000 и оканчивается на 7 вкладка «Простые делители»
    сумма min и max простых делителей — палиндром, больше 60 000 (ЕГЭ 2025) str(M) == str(M)[::-1]
    M — простое, больше 80 000, содержит «567» ровно раз (ЕГЭ 2026); разность max − min простых — простое с ≥ 4 цифрами 1 вкладка «M — простое»
    сумма различных простых делителей, числа меньше X по убыванию вкладка «По убыванию»
    произведение ровно двух простых: «ровно одна цифра 5» (ЕГЭ 2025), «ровно две 3», «67» / «16» ровно раз (ЕГЭ 2026, демо 2027), «1 или 3» (Крылов) шаблон Б, как в примере
    произведение ровно трёх простых, каждый с одной цифрой 1 (ЕГЭ 2025), с 2 или 3 len(p) == 3 and all(…) — вкладка «Три множителя»
    «три различных простых множителя» len(p) == 3 and len(set(p)) == 3: set до проверки длины превратит 60 = 2·2·3·5 в «три»
    N = 2^m · 3^n, m чётное, n нечётное, на отрезке делители не нужны — перебор степеней — вкладка «Степени»
    шестизначные без цифры 1 = нечётное кратное 103 + 3^p (Крылов-2026 в1, в2), «чётное кратное 197 + 5^n» (СтатГрад) вкладка «Сумма со степенью»
    девятизначные N = (число делителей) + кратное 23, пять наибольших; N = S + K + m, m оканчивается на 23 x = n - len(deliteli(n)), x > 0 and x % 23 == 0; перебор сверху
    «ровно 3 нетривиальных делителя» на отрезке в 100 млн; «ровно 3 чётных делителя» 5 делителей — только p⁴; три чётных — только 2 · p²: перебираем простые p (как во вкладке «Ровно три делителя»)
    «множество разностей сомножителей содержит не меньше трёх чисел ≤ 100» пары (d, n // d) от корня вниз, break, когда разность > 100 

    # №25, своя задача: «?» — ровно одна чётная цифра, «*» — любые цифры. Числа не больше 10^9 по маске 4?7*9?1,
# делящиеся на 3131; вывести число и частное
# Ответ: 46748961 14931
# Ответ: 407314921 130091
# Ответ: 427415941 136511
# Ответ: 427916901 136671
# Ответ: 447516961 142931
# Ответ: 467617981 149351
# Ответ: 487405901 155671
from fnmatch import fnmatch

K = 3131
for x in range(K, 10**9 + 1, K):
    if fnmatch(str(x), '4[02468]7*9[02468]1'):     # [02468] — одна цифра из перечисленных
        print(x, x // K)
    В fnmatch квадратные скобки — «один символ из перечисленных». Если оставить обычный ?, подойдут и нечётные цифры: на задаче СтатГрада так выходит 12 чисел вместо 5. * при этом остаётся любой. Если «любая последовательность чётных цифр» — это уже не fnmatch: регулярка [02468]* (re.fullmatch).

    # №25, своя задача: числа отрезка [10^7; 3 · 10^7] по маске 1*44*1, у которых ровно 3 делителя; вывести числа
# Ответ: 10426441
# Ответ: 10699441
# Ответ: 16168441
# Ответ: 16394401
# Ответ: 17884441
# Ответ: 18241441
from fnmatch import fnmatch
from math import isqrt


def deliteli(n):
    d = set()
    for i in range(1, isqrt(n) + 1):
        if n % i == 0:
            d.add(i)
            d.add(n // i)
    return sorted(d)


# ровно три делителя (1, p, p²) — только у квадратов простых: перебираем p, а не все 20 миллионов чисел
for p in range(isqrt(10**7), isqrt(3 * 10**7) + 1):
    n = p * p
    if 10**7 <= n <= 3 * 10**7 and len(deliteli(p)) == 2 and fnmatch(str(n), '1*44*1'):
        print(n)
    Делители идут парами, без пары только корень. Поэтому нечётное число делителей бывает только у квадрата, а ровно три (1, p, p²) — только у квадрата простого. Перебираем не 20 миллионов чисел, а p — от корня из начала до корня из конца отрезка, это 2 тысячи чисел. Так же: «ровно 3 нетривиальных» (5 делителей) — только p⁴; «ровно 3 чётных делителя» — только 2 · p².

    # №25, своя задача: M — наибольший простой делитель числа, не считая самого числа (нет — M = 0). Первые 5 чисел

    Подробнее: перебор чисел маски — когда делитель маленький

    Кратных 13 до 10¹⁰ — 770 миллионов, fnmatch будет считать минут десять. Тогда наоборот: перебираем числа маски. На месте каждого ? — любая цифра, на месте * — от 0 до L цифр, где L = (цифр в границе) − (цифр в маске без *). Числа маски — их всего около миллиона — проверяем на делимость:

    # №25, своя задача: сколько чисел не больше 10^10 соответствуют маске 5?1*7?3 и делятся на 13; наибольшее из них.
# Делитель маленький: кратных 13 до 10^10 — 770 миллионов, fnmatch не дождаться. Перебираем числа маски.
# Ответ: 85470 5919998773
from itertools import product

res = []
for L in range(0, 5):                      # «*» — от 0 до 4 цифр: без «*» в маске 6 цифр, всего не больше 10
    for z in product('0123456789', repeat=2 + L):          # две «?» и L цифр на месте «*»
        x = int('5' + z[0] + '1' + ''.join(z[2:]) + '7' + z[1] + '3')
        if x <= 10**10 and x % 13 == 0:
            res.append(x)
print(len(res), max(res))
    product('0123456789', repeat=k) перебирает все наборы из k цифр. Если в маске две *, числа выходят не по порядку: соберите в список и выведите sorted. Ориентир: кратных до 10 миллионов — шаблон А, ждём секунды; больше 100 миллионов — этот способ.

    Типичные ошибки¶

    Скрытые ловушки — проверены запуском

    • Делители — в множество, а не в список. У квадрата i == n // i, и в списке корень окажется дважды: на отрезке [10 200; 10 210] «ровно 4 делителя» имеют 10202 и 10207, а со списком в ответ попадёт ещё 10201 = 101² (у него 3 делителя): 
      # №25, ловушка: делители в список вместо множества. Числа отрезка [10 200; 10 210] ровно с 4 делителями:
# у квадрата 101² = 10201 корень 101 попадает в список дважды — и 3 делителя «превращаются» в 4
# Ответ: множество: [10202, 10207]
# Ответ: список: [10201, 10202, 10207]
from math import isqrt


def deliteli(n):                 # верно: множество
    d = set()
    for i in range(1, isqrt(n) + 1):
        if n % i == 0:
            d.add(i)
            d.add(n // i)
    return sorted(d)


def deliteli_spisok(n):          # ошибка: список — при i == n // i корень добавится два раза
    d = []
    for i in range(1, isqrt(n) + 1):
        if n % i == 0:
            d.append(i)
            d.append(n // i)
    return sorted(d)


print('множество:', [n for n in range(10200, 10211) if len(deliteli(n)) == 4])
print('список:', [n for n in range(10200, 10211) if len(deliteli_spisok(n)) == 4])
    • Корень — включительно. range(1, round(n ** 0.5)) (так в разборе на Решу ЕГЭ) у квадратов теряет корень: «ровно 3 делителя» до 200 — верно 4, 9, 25, 49, 121, 169, так — ни одного. Пишите range(1, isqrt(n) + 1).
    • В prostye — последний множитель после цикла. Без if n > 1: p.append(n) у числа 1103294351 = 163 · 167 · 40531 «останется» два множителя, оба с 16, — и оно встанет первым в ответ демоверсии вместо 1103299319.
    • len(d) > 1 вместо «список не пуст». У p² один нетривиальный делитель p, и M = p + p = 2p. Проверка «больше одного делителя» такие числа выбрасывает: 822649 = 907², M = 1814 оканчивается на 4, а в ответ не попадёт. Пишите if d.
    • «Ровно один раз» — count(...) == 1, а '16' in str(q) — «хотя бы раз». На демоверсии ответ случайно тот же, на другом числе — нет.
    • set от множителей — только когда сказано «различные». «Не обязательно различных»: 49 = 7 · 7 — это два множителя, а set оставит один. «Три различных» — len(p) == 3 and len(set(p)) == 3.
    • Простые множители — через prostye, а не через все делители. Для чисел около миллиарда список делителей каждого числа — 30 тысяч шагов: на демоверсии только первое число ищется 16 секунд, а все пять через prostye — 10–12.
    • Шаг маски — с K, а не с 0. range(0, …, K) проверит и 0: маске *0 он соответствует, а натуральным не является.
    • «Не превышающих» — включительно: range(K, 10**10 + 1, K). Обычно 10¹⁰ под маску не подходит, но с маской 1*0 и K = 10⁹ без + 1 потеряется само 10¹⁰.
    • Маленький K — fnmatch не дождаться. Шаг 1917 до 10¹⁰ — 5 миллионов чисел, 4 с; шаг 23 до 10⁹ — 43 миллиона, 37 с (можно подождать); шаг 13 до 10¹⁰ — 770 миллионов — «Подробнее: перебор чисел маски» (0,5 с).
    • «Не считая самого числа» у простых делителей. У простого n разложение — [n]; если взять p[-1], M окажется самим числом. Пишите if len(p) > 1.
    • Шаг для двух делителей — НОК, а не произведение и не «простые без повторов». Для 31 и 2031 НОК = 31 · 2031, для 6 и 10 — 30, для 4 и 6 — 12.
    • «Большие 800 000» — первым проверяется 800 001: в цикле n += 1 перед проверкой. «Не меньше» — с самого числа.
    • / вместо // — в ответе 183235.0.
    • max() и min() от пустого списка — ошибка ValueError у простых чисел; sum([]) = 0, а sum(d) // len(d) — деление на ноль. Сначала if d.
    • В fnmatch — строка: fnmatch(str(x), …); маску переписывайте посимвольно, лишний или пропущенный ? — ни одного числа.
    • «Сумма всех делителей» — с единицей и самим числом, если не сказано «не считая»; это частая потеря балла.
    • Перебор «с запасом» (for n in range(800001, 801000), взять первые пять из вывода) тоже годится, но если пяти не набралось — увеличьте диапазон, а не берите меньше.
    • Проверьте функции на маленьких числах перед задачей: deliteli(16) = [1, 2, 4, 8, 16], prostye(12) = [2, 2, 3], prostye(13) = [13].
