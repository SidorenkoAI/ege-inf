    №16. Рекурсивные функции¶

    Python можно вручную ~5 мин 1 балл без файла

    Коротко

    Переписать функцию из условия как есть, над ней @lru_cache(None), перед ответом — прогрев: for i in range(1, N + 1): F(i).

    Как узнать задачу¶

    • «Алгоритм вычисления значения функции F(n), где n — натуральное число, задан соотношениями: F(n) = … при n ≤ …; F(n) = … при n > …».
    • Спрашивают значение выражения с большими n (в демоверсии — около 3000): F(3038) − F(3037), частное, «сколько n от 1 до 1000, для которых…».

    Шаблон¶

    # №16: F(n) = n при n <= 3;  F(n) = n * F(n - 1) при n > 3.
# Чему равно значение выражения (F(2026) - F(2025)) / F(2024)?
# Ответ: 4100625
from functools import lru_cache


@lru_cache(None)                 # запоминать уже посчитанные значения
def F(n):
    if n <= 3:                   # условие переписываем как есть
        return n
    return n * F(n - 1)


for i in range(1, 2027):         # прогрев: считаем по порядку снизу вверх,
    F(i)                         # тогда рекурсия не уходит вглубь

print((F(2026) - F(2025)) // F(2024))     # «/» в условии -> «//» в Python

    Что менять под задачу:

    В условии В шаблоне
    соотношения F(n) тело def F(n) — построчно, условия if в том же порядке
    самое большое n в выражении граница прогрева: range(1, N + 1)
    выражение последняя строка print(…)
    деление «/» // — числа целые и огромные, / даст ошибку или потерю точности

    Три строки, которые не меняются: from functools import lru_cache, @lru_cache(None) над функцией и цикл прогрева. Их стоит писать в №16 всегда — даже если кажется, что задача простая.

    Пример с разбором¶

    Задача (своя, как в демоверсии). F(n) = n при n ≤ 3; F(n) = n · F(n − 1) при n > 3. Чему равно значение выражения (F(2026) − F(2025)) / F(2024)?

    Решение — шаблон выше. Функцию переписываем дословно, прогреваем до 2026 (самое большое n в выражении), деление пишем через //. Программа печатает 4100625. Ответ: 4100625.

    Проверка вручную: сократить

    F(2026) = 2026 · F(2025), поэтому F(2026) − F(2025) = F(2025) · (2026 − 1) = 2025 · F(2025). И F(2025) = 2025 · F(2024). Значит, всё выражение = 2025 · 2025 · F(2024) / F(2024) = 2025² = 4100625.

    Приём «выразить большое через меньшее и сократить» работает для разностей и частных, когда шаг рекурсии один (F(n − 1)) или два (F(n − 2)): начало ряда сокращается, считать его не нужно.

    Зачем кэш и прогрев¶

    Если F(n) вызывает две другие F (например, F(n − 1) + F(n − 2)), то без кэша число вызовов удваивается на каждом шаге — F(100) не досчитается и за годы. lru_cache запоминает уже посчитанные значения, и каждое F(k) считается один раз. Пример — вкладка «Ветвление» в разделе «Разновидности».

    Вызов F(2026) сразу уходит в глубину: F(2025), F(2024), … — 2000 вложенных вызовов. Python по умолчанию разрешает около 1000, и программа падает с RecursionError.

    Прогрев считает F(1), F(2), F(3), … по порядку. Каждое следующее значение берёт предыдущее из кэша, поэтому вглубь рекурсия не уходит ни разу.

    Прогрев идёт от базы — от тех n, где F известна сразу. Обычно база внизу (n ≤ 3), и цикл идёт вверх. Если база вверху (F(n) = n при n ≥ 5000, а F(n) выражается через F(n + 3)), цикл идёт вниз: range(5000, 0, -1) — вкладка «Рекурсия вверх» ниже.

    Почему не sys.setrecursionlimit

    Во многих разборах советуют поднять лимит: sys.setrecursionlimit(10000). Без кэша это работает, а вместе с lru_cache — нет: мы проверили на Windows, на Python 3.12 программа всё равно падает с RecursionError уже при n ≈ 700, а на Python 3.11 при n ≈ 1500 молча закрывается без ответа. Прогрев работает на любой версии — поэтому он в шаблоне, а лимит не нужен.

    Разновидности¶

    Условие Как записать
    F(n) = … при n ≤ 3 if n <= 3: return … — знак < или <= строго как в условии
    ветвление «если n чётно / нечётно» if n % 2 == 0: return … и дальше по условию
    разность или частное огромных F (факториалы) шаблон; для проверки — сократить вручную (пример выше)
    «сколько n от 1 до 1000, для которых F(n) …» цикл for n in range(1, 1001) со счётчиком — он же прогрев (вкладка «Ветвление»)
    две функции F и G друг через друга у обеих @lru_cache(None); прогревать обе в одном цикле (вкладка)
    F(n) выражается через F(n + 1), F(n + 2), … («вверх») прогрев от базы — сверху вниз (вкладка)
    целая часть [x] int( … ) вокруг всего выражения в скобках (вкладка)
    «/» — деление нацело («//» в условии) // прямо в функции: F(n - 1) // 3
    маленькое n («найдите F(5)») можно раскрутить вручную: F(5) через F(4), …, до базы, потом собрать обратно
    «наименьшее n, для которого F(n) = 12» n = 1, while F(n) != 12: n += 1 — цикл снизу вверх, он же прогрев
    сумма «F(i) от i = 1 до n − 1» sum(F(i) for i in range(1, n)) — range не включает n
    функция делит, и дробь сокращается только в конце (G(n) = n / 4 + 18) Fraction(n, 4) из fractions — точно; n // 4 даёт неверный ответ
    F(n) не задана при каком-то n (F(2)), но и не нужна прогревать только нужные n, например нечётные: range(1, N + 1, 2)
    F(a, b) от двух чисел, интервал в миллиард чисел, 2⁶³ понять, что считает F (сумма цифр, число единиц, НОД, a · b), проверить догадку перебором на малых и считать без перебора (вкладка)
    числа слишком велики даже с кэшем (F(320 726), F(247 563)) сократить вручную, как в «Проверке вручную»; формулу проверить на малых n 
    # №16, ветвление: F(n) = n при n < 3;
# F(n) = F(n - 1) + F(n - 2), если n > 2 и n чётно;
# F(n) = F(n - 2) + n,        если n > 2 и n нечётно.
# Сколько существует чисел n от 1 до 1000, для которых F(n) делится на 3?
# Ответ: 333
from functools import lru_cache


@lru_cache(None)                 # без кэша F(1000) не досчитается: вызовы ветвятся
def F(n):
    if n < 3:
        return n
    if n % 2 == 0:
        return F(n - 1) + F(n - 2)
    return F(n - 2) + n


count = 0
for n in range(1, 1001):         # цикл по n снизу вверх — он же прогрев
    if F(n) % 3 == 0:
        count += 1
print(count)

    # №16, две функции: F(n) = G(n) = 1 при n = 1;
# F(n) = n + G(n - 1) и G(n) = F(n - 1) - 3 при n > 1.
# Чему равно F(2025) + G(2024)?
# Ответ: 2044241
from functools import lru_cache


@lru_cache(None)
def F(n):
    if n == 1:
        return 1
    return n + G(n - 1)


@lru_cache(None)                 # кэш нужен обеим функциям
def G(n):
    if n == 1:
        return 1
    return F(n - 1) - 3


for i in range(1, 2026):         # прогрев обеих в одном цикле
    F(i)
    G(i)

print(F(2025) + G(2024))

    # №16, рекурсия «вверх»: F(n) = n при n >= 5000;  F(n) = n + F(n + 3) при n < 5000.
# Чему равно F(1)?
# Ответ: 4172502
from functools import lru_cache


@lru_cache(None)
def F(n):
    if n >= 5000:
        return n
    return n + F(n + 3)


for i in range(5000, 0, -1):     # прогрев ОТ БАЗЫ: база вверху (n >= 5000), идём вниз
    F(i)

print(F(1))

    # №16, целая часть: F(n) = 1 при n = 1;  F(n) = [F(n - 1) / 2 + n / 3] + n при n > 1,
# где [x] — целая часть числа x. Чему равно F(3000)?
# Ответ: 7997
from functools import lru_cache


@lru_cache(None)
def F(n):
    if n == 1:
        return 1
    return int(F(n - 1) / 2 + n / 3) + n    # [ ] -> int( ) вокруг ВСЕГО выражения в скобках


for i in range(1, 3001):
    F(i)

print(F(3000))

    # №16, огромный интервал: F(0) = 0;  F(n) = F(n div 10) + (n mod 10) при n > 0.
# Сколько чисел n от 1 000 000 000 до 3 000 000 000, для которых F(n) > F(n + 1)?
# Ответ: 200000000
from functools import lru_cache


@lru_cache(None)
def F(n):
    if n == 0:
        return 0
    return F(n // 10) + n % 10


# 1. Что считает F? Сумму цифр. Когда F(n) > F(n + 1)? Догадка: когда n оканчивается на 9
#    (при +1 девятки становятся нулями). Проверяем догадку перебором на маленьких числах:
for n in range(1, 100000):
    if (F(n) > F(n + 1)) != (n % 10 == 9):
        print('догадка неверна:', n)

# 2. Считаем без перебора: в интервале подходит каждое десятое число
lo, hi = 1000000000, 3000000000
first = lo + (9 - lo % 10) % 10          # первое число ≥ lo, которое оканчивается на 9
print(len(range(first, hi + 1, 10)))

    Миллиард чисел Python перебирает десятки минут. Порядок такой: напечатать F для маленьких n и понять, что она считает; проверить догадку перебором на малых числах; посчитать ответ без перебора. Что встречалось на Решу ЕГЭ: F — сумма цифр (F(n) > F(n + 1) ⇔ n оканчивается на 9), число единиц в двоичной записи (перебирать только 2 ** i + 2 ** j), сумма чётных цифр (= 0, когда цифры только 0, 1, 3, 5, 7, 9), НОД (вычитание по 14 — зависит от остатка n по модулю 14), F(a, b) = a · b. Для «сумма цифр равна 159 среди чисел меньше 2⁶³» нужен счёт по разрядам — это уже за рамками шаблона.

    Типичные ошибки¶

    Скрытые ловушки — проверены запуском

    • Целая часть — от всего выражения. [F(n − 1)/2 + n/3] — это int(F(n - 1) / 2 + n / 3), а не F(n - 1) // 2 + n // 3: в примере выше «по частям» выходит 7996 вместо 7997.
    • int неточен на огромных числах. int(a / b) считает через дробное число и при числах длиннее 15 цифр теряет последние цифры: int((10**17 + 5) / 3) ошибается, (10**17 + 5) // 3 — нет. Для одной дроби пишите a // b, для суммы дробей — общий знаменатель: [a/2 + b/3] = (3*a + 2*b) // 6.
    • Отрицательные числа: int(-7 / 2) = −3, а целая часть −3,5 — это −4 (так считает //).
    • Прогрев не в ту сторону. Если F(n) выражается через F(n + 1), прогрев снизу вверх снова упирается в RecursionError. Прогрев — от базы.
    • Дробь посередине. В задаче Решу ЕГЭ G(n) = n / 4 + 18, а ответ — целый, потому что дальше всё умножается на 8. n // 4 молча даёт 2 703 080 вместо 2 703 082, в похожей задаче с n / 6 — 3 396 732 вместо 3 396 736. Точно — Fraction(n, 4) (обычное / тут случайно сработало, но с дробями вроде 1/6 может ошибиться).
    • Сумма «до n − 1», записанная до n. sum(F(i) for i in range(1, n + 1)) вызывает F(n) внутри F(n) — бесконечная рекурсия и RecursionError.
    • Граница интервала тоже считается. «4 · 10⁷ ≤ n ≤ 9 · 10⁷»: само 90 000 000 подходит, без него — 559 872 вместо 559 873.
    • RecursionError / программа молча закрылась — забыт прогрев (см. предупреждение «Почему не sys.setrecursionlimit»).
    • Программа «висит» — функция ветвится, а кэша нет.
    • / вместо //. Деление / даёт дробное число: ответ вида 4100625.0, при ответе длиннее 15 цифр — потерю последних цифр, а при огромном частном — ошибку OverflowError.
    • Перепутаны границы: «при n ≤ 3» и «при n < 3» — разные функции.
    • Прогрев не до конца: граница цикла должна дойти до самого большого n в выражении (range(1, N + 1)).
    • Кэш только у одной из двух функций — вторая пересчитывается заново, программа «висит».
    • Ответ отрицательный, а в условии «натуральное число» — ошибка при переписывании формулы. Сверьте каждую строку функции с условием.
