    №23. Графы: кратчайший путь и число путей¶

    Python ~12 мин 1 балл файл .txt

    Коротко

    Рёбра из файла — в список (a, b, w). Таблица d = [10**10] * 1001, у старта d[1] = 0. Столько раз, сколько рёбер, проходим по всем рёбрам: d[b] = min(d[b], d[a] + w). Ответ — int(round(d[100], 6)). Самый длинный путь — max и -10**10; через вершину — сумма двух путей; число путей — рекурсия с кэшем, как в №13.

    Как узнать задачу¶

    • «В текстовом файле содержится описание ациклического ориентированного взвешенного графа». В каждой строке три числа L M W: ребро ведёт из вершины L в вершину M и имеет вес (длину) W.
    • Вопрос — в конце: «целая часть длины кратчайшего пути из вершины 1 в вершину 100». Бывает самый длинный путь, путь через вершину или в обход неё, число рёбер, количество различных путей.
    • В условии прямо сказано: «следует написать программу». Строк в файле до 200, номера вершин до 1000 и идут не подряд, числа разделены «произвольным количеством пробелов и/или табуляций».

    Слова условия: ориентированный — по ребру идём только из L в M; ациклический — по стрелкам нельзя вернуться в вершину, где уже были (поэтому путей конечное число); взвешенный — у каждого ребра своя длина.

    Задание новое в ЕГЭ-2027. До 2027 года №23 было про число программ исполнителя — теперь это №13. Видео «задание 23» 2025–2026 годов — про старый номер.

    Шаблон¶

    # №23, демоверсия ЕГЭ-2027 (файл 23.txt): целая часть длины кратчайшего пути
# из вершины 1 в вершину 100 ациклического ориентированного взвешенного графа.
# Ответ: 10971
edges = []                                    # все рёбра: (откуда, куда, вес)
for s in open('23.txt'):
    a, b, w = s.split()                       # split() съест любые пробелы и табуляции
    edges.append((int(a), int(b), float(w)))  # номера — int, вес дробный — float

d = [10**10] * 1001                           # d[v] — длина лучшего пути из 1 в v; 10**10 — «пока не дошли»
d[1] = 0                                      # старт: до самой себя — 0
for _ in range(len(edges)):                   # проходов — сколько рёбер (с запасом)
    for a, b, w in edges:
        d[b] = min(d[b], d[a] + w)            # в b короче через ребро a → b?

print(int(round(d[100], 6)))                  # целая часть; round — от погрешности float

    Как это работает. d[v] — длина лучшего пути из 1 в v, который уже нашли. Сначала нашли только путь из 1 в саму себя (0), до остальных вершин «пока не дошли» — 10**10, больше любого настоящего пути (максимум 200 · 10 000 = 2 000 000). Ребро a → b предлагает путь в b через a: d[a] + w; если он короче записанного — запоминаем. Рёбра в файле идут вперемешку, поэтому одного прохода мало: на файле демоверсии после 1 прохода до 100 ещё не дошли, после 3 — 11782, верное 10971 — только с 5-го. Проходов «сколько рёбер» хватит всегда: каждый проход продлевает найденные пути хотя бы на одно ребро, а в пути не больше рёбер, чем всего в файле. (Это алгоритм Беллмана — Форда; 200 × 200 = 40 000 шагов — мгновенно.)

    Что менять под задачу:

    В условии В шаблоне
    «из вершины с номером 1» d[1] = 0 (другая вершина — её номер)
    «в вершину с номером 100» d[100] в ответе
    «кратчайшего пути» min и «пока не дошли» 10**10
    «самого длинного пути», «пути наибольшей длины» max и -10**10 (вкладка «Самый длинный»)
    «L ≤ 1000, M ≤ 1000» список на 1001 элемент — чтобы был d[1000]
    «W — положительное вещественное число» float(w); номера — int
    «произвольное количество пробелов и/или табуляций» s.split() — без аргумента
    «запишите целую часть» int(round(…, 6)) — см. «Типичные ошибки»

    Пример с разбором¶

    Задача (типовой пример из условия демоверсии ЕГЭ-2027). В файле primer.txt 8 строк — 8 рёбер:

    Строка файла Ребро
    100 12 1.0 100 → 12, длина 1
    6 7 7.0 6 → 7, длина 7
    6 1 1.0 6 → 1, длина 1
    1 7 5.5 1 → 7, длина 5,5
    7 100 2.0 7 → 100, длина 2
    4 100 8.0 4 → 100, длина 8
    1 100 12.0 1 → 100, длина 12
    1 4 2.5 1 → 4, длина 2,5

    Найдите целую часть длины кратчайшего пути из вершины 1 в вершину 100.

    Решение. Шаблон, только файл другой. Как меняется таблица d по проходам (строки — в порядке файла):

    d[1] d[4] d[6] d[7] d[12] d[100]
    сначала 0 10¹⁰ 10¹⁰ 10¹⁰ 10¹⁰ 10¹⁰
    после 1-го прохода 0 2,5 10¹⁰ 5,5 10¹⁰ 7,5
    после 2-го 0 2,5 10¹⁰ 5,5 8,5 7,5
    дальше не меняется

    На 1-м проходе ребро 100 12 стоит первым, когда до 100 ещё не дошли, — поэтому d[12] появляется только на 2-м. В вершину 6 не ведёт ни одно ребро: d[6] так и остаётся 10**10, а ребро 6 1 ничего не меняет.

    # №23: типовой пример из условия демоверсии ЕГЭ-2027 (файл primer.txt, 8 рёбер) —
# кратчайший путь из 1 в 100. Печатаем всю таблицу d по вершинам примера и ответ.
# Ответ: 1 0 4 2.5 6 10000000000 7 5.5 12 8.5 100 7.5
# Ответ: 7
edges = []
for s in open('primer.txt'):
    a, b, w = s.split()
    edges.append((int(a), int(b), float(w)))

d = [10**10] * 1001
d[1] = 0
for _ in range(len(edges)):
    for a, b, w in edges:
        d[b] = min(d[b], d[a] + w)

print(*[f'{v} {d[v]}' for v in (1, 4, 6, 7, 12, 100)])   # таблица: вершина и d
print(int(round(d[100], 6)))

    Ответ: 7. На файле демоверсии (23.txt) тот же шаблон печатает 10971 — это ответ демоверсии.

    Проверка вручную

    Из 1 в 100 ведут три пути: прямо — 12; через 4 — 2,5 + 8 = 10,5; через 7 — 5,5 + 2 = 7,5. Кратчайший — 7,5, целая часть — 7. Прямое ребро не обязательно самое короткое: в обход бывает короче. Вручную так решают только маленькие графы; в файле 200 рёбер и миллиарды путей (в демоверсии из 1 в 100 — 2 033 652 335 путей) — поэтому и нужна программа.

    Разновидности¶

    Демоверсия — пока единственная официальная задача; разновидности ниже — из проекта ФИПИ («оптимальный путь, число путей»), банков КомпЕГЭ и Решу ЕГЭ и разборов. Все ответы примеров проверены вторым способом — точным счётом по порядку вершин на дробях (Fraction).

    Условие Как записать
    «из вершины 4 в вершину 298» — другие номера d[4] = 0, ответ d[298]; удобнее функцией put(start) (вкладка «Через вершину»)
    «самого длинного пути», «пути наибольшей длины» max и -10**10 (вкладка)
    «проходящего через вершину 91» put(1)[91] + put(91)[100] — до 91 плюс от 91 (вкладка)
    «проходящего сначала через 25, а затем через 50» put(A)[25] + put(25)[50] + put(50)[B]
    «через обе вершины 91 и 474» (порядок не сказан) оба порядка и min: в ациклическом графе возможен только один, второй даст 10¹⁰ и больше
    «не проходящего через вершину 312» выбросить её рёбра: edges = [(a, b, w) for a, b, w in edges if a != 312 and b != 312] (вкладка)
    «через 400 и не через 96» сначала выбросить 96, потом put(4)[400] + put(400)[298]
    «проходящего по ребру из 46 в 825» put(1)[46] + ves[(46, 825)] + put(825)[100], ves — веса по парам (вкладка «Ребро»)
    «не проходящего по ребру из 56 в 100» выбросить одно ребро: if (a, b) != (56, 100) (вкладка «Ребро»)
    «первое ребро пути — из A в C, последнее — из D в B» ves[(A, C)] + put(C)[D] + ves[(D, B)]
    «только рёбра с весом не менее 10» при чтении брать ребро, только если w >= 10
    «наименьшее (наибольшее) количество рёбер в пути» вес каждого ребра — 1: edges.append((int(a), int(b), 1)) (вкладка)
    «количество различных путей из 1 в 100» рекурсия с кэшем, как в №13 (вкладка «Число путей»)
    число путей через вершину / по ребру / не через вершину f(1, X) * f(X, 100) / f(1, a) * f(b, 100) / if x == X: return 0
    число путей «не более 10 рёбер», «ровно 25 рёбер» третий аргумент — сколько рёбер ещё можно (вкладка «Не больше K рёбер»)
    длины от вершины до всех; сколько вершин достижимо после шаблона: [x for x in d if x < 10**10] — длины до всех достижимых, len(…) — сколько их 
    # №23 (файл демоверсии 23.txt): целая часть длины САМОГО ДЛИННОГО пути из вершины 1 в вершину 100.
# Ответ: 242730
edges = []
for s in open('23.txt'):
    a, b, w = s.split()
    edges.append((int(a), int(b), float(w)))

d = [-10**10] * 1001                          # «пока не дошли» — теперь очень МАЛЕНЬКОЕ число
d[1] = 0
for _ in range(len(edges)):
    for a, b, w in edges:
        d[b] = max(d[b], d[a] + w)            # min → max

print(int(round(d[100], 6)))

    Меняются две вещи: min → max и «пока не дошли» → очень маленькое число. Если забыть второе, max выберет «бесконечность»: напечатается 10000241413.

    # №23 (файл демоверсии 23.txt): целая часть длины кратчайшего пути из 1 в 100,
# 1) проходящего через вершину 91; 2) не проходящего через вершину 312.
# Ответ: 11609
# Ответ: 13714
edges = []
for s in open('23.txt'):
    a, b, w = s.split()
    edges.append((int(a), int(b), float(w)))


def put(start):                               # тот же шаблон, но старт — любой: d[v] — путь из start в v
    d = [10**10] * 1001
    d[start] = 0
    for _ in range(len(edges)):
        for a, b, w in edges:
            d[b] = min(d[b], d[a] + w)
    return d


print(int(round(put(1)[91] + put(91)[100], 6)))         # через 91: от 1 до 91 плюс от 91 до 100

edges = [(a, b, w) for a, b, w in edges if a != 312 and b != 312]   # без вершины 312 — без её рёбер
print(int(round(put(1)[100], 6)))

    Длины складываются: путь до 91 плюс путь от 91. (В №13 и в «числе путей» — произведение: там считают варианты, а не длину.)

    # №23 (файл демоверсии 23.txt): целая часть длины кратчайшего пути из 1 в 100,
# 1) проходящего по ребру 46 → 825; 2) не проходящего по ребру 56 → 100.
# Ответ: 12902
# Ответ: 15962
edges = []
for s in open('23.txt'):
    a, b, w = s.split()
    edges.append((int(a), int(b), float(w)))


def put(start):
    d = [10**10] * 1001
    d[start] = 0
    for _ in range(len(edges)):
        for a, b, w in edges:
            d[b] = min(d[b], d[a] + w)
    return d


ves = {(a, b): w for a, b, w in edges}        # вес ребра по паре вершин: ves[(46, 825)]
print(int(round(put(1)[46] + ves[(46, 825)] + put(825)[100], 6)))   # до начала ребра + ребро + от его конца

edges = [(a, b, w) for a, b, w in edges if (a, b) != (56, 100)]     # без одного ребра
print(int(round(put(1)[100], 6)))

    # №23 (файл демоверсии 23.txt): наименьшее и наибольшее количество рёбер в пути из вершины 1 в вершину 56.
# Ответ: 4
# Ответ: 40
edges = []
for s in open('23.txt'):
    a, b, w = s.split()
    edges.append((int(a), int(b), 1))         # считаем рёбра: вес каждого ребра — 1


def put(start, big, best):                    # best — min или max, big — «пока не дошли»
    d = [big] * 1001
    d[start] = 0
    for _ in range(len(edges)):
        for a, b, w in edges:
            d[b] = best(d[b], d[a] + w)
    return d


print(put(1, 10**10, min)[56])                # наименьшее число рёбер
print(put(1, -10**10, max)[56])               # наибольшее

    Наименьшее число рёбер — «кратчайший путь», если каждое ребро длины 1; наибольшее — «самый длинный».

    # №23 (файл демоверсии 23.txt): 1) сколько различных путей ведёт из вершины 1 в вершину 100;
# 2) сколько из них проходят через вершину 91; 3) сколько не проходят через вершину 312.
# Ответ: 2033652335
# Ответ: 782470800
# Ответ: 605506251
from functools import lru_cache

edges = []
for s in open('23.txt'):
    a, b, w = s.split()
    edges.append((int(a), int(b), float(w)))


@lru_cache(None)                              # без кэша не дождаться: путей — миллиарды
def f(x, y):                                  # сколько путей из x в y — как в №13
    if x == y:
        return 1
    return sum(f(b, y) for a, b, w in edges if a == x)    # тупик: сумма пустого — 0


print(f(1, 100))
print(f(1, 91) * f(91, 100))                  # через 91 — произведение, как в №13


@lru_cache(None)
def g(x, y):                                  # то же, но в вершину 312 заходить нельзя
    if x == 312:
        return 0
    if x == y:
        return 1
    return sum(g(b, y) for a, b, w in edges if a == x)


print(g(1, 100))

    Та же функция f(x, y), что в №13: пришли в y — один путь, иначе сумма по рёбрам из x. Тупик (рёбер из x нет) — сумма пустого списка, 0. Кэш обязателен: путей больше двух миллиардов, без lru_cache программа не закончится.

    # №23 (файл демоверсии 23.txt): сколько различных путей из вершины 1 в вершину 100
# 1) содержат не более 12 рёбер; 2) содержат ровно 12 рёбер.
# Ответ: 1458956
# Ответ: 977986
from functools import lru_cache

edges = []
for s in open('23.txt'):
    a, b, w = s.split()
    edges.append((int(a), int(b), float(w)))


@lru_cache(None)
def f(x, y, k):                               # сколько путей из x в y, в которых не больше k рёбер
    if x == y:
        return 1
    if k == 0:                                # рёбра кончились, а до y не дошли
        return 0
    return sum(f(b, y, k - 1) for a, b, w in edges if a == x)


print(f(1, 100, 12))
print(f(1, 100, 12) - f(1, 100, 11))          # ровно 12 = «не больше 12» минус «не больше 11»
    Необычные разновидности (КомпЕГЭ, Лёня Шастин, Алексей Кабанов)

    Пока это задачи авторов банков, на ЕГЭ таких не было. Код ниже проверен на задачах КомпЕГЭ (ответы совпали).

    Условие Как записать
    кратчайший путь, «содержащий не более 20 рёбер» 20 проходов, каждый — по копии: new = d.copy(), в цикле new[b] = min(new[b], d[a] + w), после цикла d = new (без копии путь за проход удлиняется больше чем на ребро)
    «из путей с наименьшим числом рёбер — с наименьшей суммой» в d пары (рёбер, сумма): d = [(10**10, 0)] * 1001, d[A] = (0, 0), d[b] = min(d[b], (d[a][0] + 1, d[a][1] + w)) — пары сравниваются по первому числу, при равенстве по второму
    «кратчайший; если таких несколько — с меньшим числом рёбер; ответ — число рёбер» то же, пары (сумма, рёбер)
    «наибольший вес ребра в пути — как можно меньше» d[b] = min(d[b], max(d[a], w))
    «самый длинный путь из 2027 до любого тупика» шаблон «Самый длинный», ответ — max(d)
    «самый длинный путь, не превышающий 2000» только перебор всех путей (сумма — аргументом функции, без кэша); Кабанов: «на экзамене вряд ли»
    огромный файл: 100 000 рёбер, номера до 10 000 список на 10001; range(len(edges)) проходов — 10¹⁰ шагов, не дождаться: выходить из цикла, когда проход ничего не изменил (флаг). На файле КомпЕГЭ в 85 000 рёбер кратчайший путь — 20 проходов, 0,3 с, а самый длинный — 4805 проходов, 2 минуты; рекурсия с кэшем — мгновенно
    Подробнее: второй способ — рекурсия с кэшем, как в №13

    Так решают многие разборщики (Кабанов, Иглин, Марат, Умскул): f(x, y) — длина кратчайшего пути из x в y; в y — 0, иначе минимум «ребро + путь от его конца».

    # №23, демоверсия ЕГЭ-2027 (файл 23.txt) — второй способ: рекурсия с кэшем, как в №13.
# Целая часть длины кратчайшего пути из 1 в 100.
# Ответ: 10971
from functools import lru_cache

edges = []
for s in open('23.txt'):
    a, b, w = s.split()
    edges.append((int(a), int(b), float(w)))


@lru_cache(None)                              # обязательно: без кэша — миллиарды путей
def f(x, y):                                  # длина кратчайшего пути из x в y
    if x == y:
        return 0
    return min([w + f(b, y) for a, b, w in edges if a == x], default=10**10)   # тупик — 10**10, НЕ 0


print(int(round(f(1, 100), 6)))

    Две ловушки этого способа (проверены): тупик — 10**10, а не 0. Из тупика до y не дойти; если вернуть 0, такой «путь» окажется самым коротким. В решении к демоверсии на Решу ЕГЭ тупик возвращает 0 — на файле демо ответ случайно верный, а на других файлах выходит 287 вместо 315, 107 вместо 443 (6 задач КомпЕГЭ из 9). Без кэша не дождаться: за 10 секунд — 27 миллионов вызовов, и конца не видно. Для числа путей рекурсия — основной способ (вкладка «Число путей»).

    Ещё называют алгоритм Дейкстры (Шастин, Семёнов, Флэш). Для 200 рёбер он не нужен, а ошибиться в нём проще.

    Типичные ошибки¶

    Скрытые ловушки — проверены запуском

    • int от дробной суммы теряет единицу. Дробные веса в компьютере хранятся неточно: 30.6 + 83.1 + 5.3 даёт 118.99999999999999, и int пишет 118 вместо 119 (свой файл drobi.txt, вывод — ниже). На задаче КомпЕГЭ 31554 (самый длинный путь, веса с одним знаком после точки) выходит 3362.9999999999995 — 3362 вместо
    • Поэтому в шаблоне int(round(d[100], 6)): сначала округлить до 6 знаков (погрешность исчезнет), потом взять целую часть. Python 3.11 и 3.12 — одинаково.
    • Мало проходов — ошибки нет, ответ больше верного. На демоверсии: 1 проход — 10000000000 (до 100 не дошли), 3 прохода — 11782, верно 10971 — с 5-го. Проходов — len(edges), не «на глаз».
    • Тупик = 0 в рекурсии (как в решении Решу ЕГЭ к демоверсии): на демо ответ случайно верный, на других файлах — меньше верного (315 → 287, 443 → 107).
    • round(d[100]) без 6 — это округление, а не целая часть: 7,5 → 8 (в примере ответ 7).
    # №23 (свой файл drobi.txt, веса с одним знаком после точки): целая часть длины кратчайшего пути из 1 в 100.
# Печатаем d[100] как есть, int без round и int с round.
# Ответ: 118.99999999999999 118 119
edges = []
for s in open('drobi.txt'):
    a, b, w = s.split()
    edges.append((int(a), int(b), float(w)))

d = [10**10] * 1001
d[1] = 0
for _ in range(len(edges)):
    for a, b, w in edges:
        d[b] = min(d[b], d[a] + w)

print(d[100], int(d[100]), int(round(d[100], 6)))   # путь 1 → 2 → 3 → 100: 30.6 + 83.1 + 5.3 = 119 ровно
    • float, а не int у веса. int('4582.0') — ValueError: в файле демоверсии все веса записаны с .0.
    • split(' ') вместо split(). Между числами по нескольку пробелов и табуляций: split(' ') даёт пустые строки — ValueError: too many values to unpack.
    • Пустая строка в файле (часто последняя) — ValueError: not enough values to unpack (expected 3, got 0). Если такая есть — пропускать: if s.split(): перед разбором строки.
    • Список короче номеров вершин. Номера до 1000 — список на 1001 элемент; [10**10] * 100 — IndexError на первой же строке (вершина 655). В «огромных» файлах номера до 10 000.
    • Самый длинный путь с 10**10. При max «пока не дошли» — -10**10, иначе ответ 10000241413.
    • Через вершину — сложение длин, а не произведение. Произведение — для числа путей (как в №13).
    • Перепутали «сначала 25, затем 50» и «через обе». В первом случае порядок задан; во втором — проверить оба.
