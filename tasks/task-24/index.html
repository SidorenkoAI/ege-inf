    №24. Обработка строки из файла¶

    Python ~18 мин 1 балл файл .txt

    Коротко

    Сначала понять, что спрашивают — от этого зависит шаблон.

    • А. Подстрока с условием («буква Y встречается ровно 80 раз», «начинается с чётной цифры»…) — двойной цикл: for l, for r in range(l + mx, len(s)), t = s[l:r + 1]; условие → mx = max(mx, len(t)), антиусловие (дальше будет только хуже) → break.
    • Б. Корректная запись (арифметическое выражение, число в системе счисления) — регулярное выражение: num = r'(0|[1-9][0-9]*)', expr = num + r'([-*]' + num + r')*', max(len(m.group()) for m in re.finditer(expr, s)).

    Как узнать задачу¶

    • «Текстовый файл состоит из …» — в файле одна длинная строка (до 10 миллионов символов): буквы, цифры, знаки «+», «−», «*».
    • «Определите максимальное (реже минимальное) количество идущих подряд символов, среди которых…» или «…которая является корректным арифметическим выражением / записью числа».
    • В ответе — обычно длина найденного куска; бывает само число, результат суммы или номер первого символа.

    Задачи двух видов:

    Вид Как звучит Шаблон
    подстрока с условием «буква Y встречается ровно 80 раз, подстрока 2025 — не менее 90 раз», «начинается с чётной цифры, других чётных нет», «не более 240 пар DE» А — двойной цикл
    корректная запись «является корректным арифметическим выражением», «запись числа в 12-ричной системе», «римская запись» Б — регулярное выражение

    Шаблон¶

    А. Подстрока с условием — двойной цикл¶

    # №24, шаблон А: самая длинная подстрока, где 2026 встречается не менее 15 раз и ровно 40 букв Y
# Ответ: 2662
s = open('stroka.txt').readline().strip()
mx = 0
for l in range(len(s)):
    for r in range(l + mx, len(s)):      # короче найденной не смотрим
        t = s[l:r + 1]
        if t.count('Y') == 40 and t.count('2026') >= 15:    # условие задачи
            mx = max(mx, len(t))
        if t.count('Y') > 40:                               # антиусловие: дальше только хуже
            break
print(mx)

    Как это работает. l — начало подстроки, r — конец, t = s[l:r + 1] (у среза правая граница не входит — отсюда + 1). Для каждого начала растим конец, пока есть смысл:

    • условие — всё, что требует задача, дословно: t.count('Y') == 40 and t.count('2026') >= 15; выполнено — запоминаем длину;
    • антиусловие — то, что при удлинении уже не исправится: Y больше 40 — дальше их станет только больше, поэтому break, переходим к следующему началу. «Не менее 15» антиусловием быть не может — при удлинении вхождений может прибавиться;
    • range(l + mx, …) — подстроки не длиннее найденной не смотрим вовсе: так программа работает в сотни раз быстрее.

    На файле демоверсии 2026 («2025 не менее 90 раз, ровно 80 букв Y», 10 млн символов) эта программа печатает 2981 за 25–50 секунд — на экзамене можно подождать. Время растёт вместе с длиной ответа: при ответе в десятки тысяч символов — уже 15–25 минут (см. «Типичные ошибки»).

    Что менять под задачу:

    В условии В шаблоне
    «буква Y встречается ровно 80 раз» условие t.count('Y') == 80, антиусловие t.count('Y') > 80
    «не более 150 раз» условие t.count('Y') <= 150, антиусловие t.count('Y') > 150
    «не менее 90 раз» только в условии: t.count('2025') >= 90
    «нет буквы A» условие 'A' not in t, антиусловие 'A' in t
    «каждая из букв U…Z не более 100 раз» all(t.count(c) <= 100 for c in 'UVWXYZ') и any(t.count(c) > 100 for c in 'UVWXYZ')
    «начинается с S», «начинается с 2025» перед вторым циклом: if s[l] != 'S': continue (s[l:l + 4] != '2025')
    «оканчивается на CAT» в условии t.endswith('CAT') (антиусловием не бывает)
    «чётная цифра ровно одна» сначала все чётные цифры заменить одной: for c in '2468': s = s.replace(c, '0'), потом t.count('0') == 1
    «ровно 35 нечётных цифр» так же: нечётные → '1', потом t.count('1') == 35
    «пара TT», «пара WW», «00» (буквы одинаковые) не count — он не считает наложения (см. ловушки)
    минимальная длина другой шаблон — вкладка «Минимум»

    Б. Корректная запись — регулярное выражение¶

    # №24, демоверсия ЕГЭ-2027: самое длинное корректное выражение из цифр 0, 6–9 и знаков «−», «*»
# Ответ: 154
import re

s = open('24.txt').readline().strip()
num = r'(0|[1-9][0-9]*)'                 # число: 0 или без ведущего нуля
expr = num + r'([-*]' + num + r')*'      # число, потом «знак число» сколько угодно раз
print(max(len(m.group()) for m in re.finditer(expr, s)))

    Регулярное выражение описывает, как выглядит нужный кусок, а re.finditer находит все такие куски подряд слева направо. m.group() — сам найденный кусок.

    Запись Значит
    [-*], [0-9], [1-9AB] один символ из набора (- — первым, иначе это диапазон)
    x*, x+ x повторяется 0 и более раз, 1 и более раз
    x{0,4} от 0 до 4 раз
    ( … ) группа: к ней относится * после неё
    a|b или; длинный вариант — первым
    \*, \+ сами знаки «*» и «+» (вне квадратных скобок)

    Что менять под задачу:

    В условии В регулярке
    «нет незначащих (ведущих) нулей» число 0|[1-9][0-9]* — ноль отдельно, иначе первая цифра не 0
    «знаки «−» и «*»», «+ и *» [-*], [+*]
    «цифры 0, 6, 7, 8, 9» можно не уточнять: других цифр в файле нет
    «натуральные числа» без нуля: [1-9][0-9]*
    «число в 12-ричной системе» [1-9AB][0-9AB]* (цифры 0…9, A, B) — вкладка «Запись числа»
    «A, за которой следует выражение» 'A' + num + …
    «не более 40 чисел» {0,39} и поиск с каждой позиции — вкладка «Не более K чисел»

    Пример с разбором¶

    Задача (демоверсия ЕГЭ-2027, файл demo_24.txt из архива ФИПИ; тот же файл и та же задача — в демоверсии 2025). Текстовый файл состоит из цифр 0, 6, 7, 8, 9 и знаков «−» и «*». Найдите максимальное количество символов в непрерывной последовательности, которая является корректным арифметическим выражением с целыми неотрицательными числами: никакие два знака не стоят рядом, в числах нет ведущих нулей, число 0 не имеет знака.

    Решение — шаблон Б:

    Условие Код
    число без ведущих нулей: 0 или начинается не с 0 num = r'(0|[1-9][0-9]*)'
    выражение: число, потом «знак, число» сколько угодно раз num + r'([-*]' + num + r')*'
    два знака рядом нельзя, знак в начале и в конце нельзя получается само: после знака обязано идти число
    «0 не имеет знака», неотрицательные числа тоже само: выражение начинается с числа, а не со знака
    максимальное количество символов max(len(m.group()) for m in re.finditer(expr, s))

    Программа печатает 154. Ответ: 154

    Проверка на короткой строке

    Прежде чем запускать на файле, проверьте регулярку на строке, где есть все «плохие» места:

    s = '67-089*0*96--7*0-6'
print([m.group() for m in re.finditer(expr, s)])     # ['67-0', '89*0*96', '7*0-6']

    089 — ведущий ноль: выражение 67-0 обрывается, а с 89 начинается новое; -- — два знака подряд: обрыв. Всё как в условии.

    Разновидности¶

    Условие Как записать
    «никакие два соседних символа не одинаковы», «буква не рядом с буквой, цифра не рядом с цифрой», «нет KL и LK», «цифры по убыванию» счётчик серии — вкладка «Соседние символы»
    «нет подстроки XZZY», «нет двух нулей подряд» разорвать пробелом и split — вкладка «Запрещённое сочетание»
    «пары AB или CB подряд», «тройки NPO или PNO», «согласная + гласная» замены и 'AB' * k in s — вкладка «Пары подряд»
    цепочка «KLMNKLMN…», неполная группа в начале и в конце счётчик серии с условием a + b in 'KLMNK' (соседи идут по кругу)
    ровно / не более K букв (подстрок), максимум шаблон А
    «начинается с S», «других S нет», «ровно 35 нечётных цифр» (Крылов, ЕГЭ-2025) шаблон А: if s[l] != 'S': continue; нечётные → '1'
    «оканчивается на CAT», CAT не менее 4 раз, цифра 1 ровно 700 раз (Крылов) условие шаблона А t.endswith('CAT') and t.count('CAT') >= 4 and t.count('1') == 700 верно, но двойной цикл на 5 млн символов думает 20+ минут. Быстро — окна между единицами: p — позиции 1 (и края −1, len(s)), t = s[p[i - 1] + 1:p[i + 700]], хвост до последнего CAT: t = t[:t.rfind('CAT') + 3], дальше то же условие
    ровно / не менее K, минимальная длина позиции — вкладка «Минимум»
    минимальная, «гласная ровно одна, последовательность кончается ею», «T ровно 63 раза» (ЕГКР, 2025–2026) позиции T после последней гласной: от 63-й с конца T до гласной
    минимальная, «не менее 10 000 слов» («слово» — буквы между цифрами) re.finditer('[A-Z]+', s) → список слов, окно из 10 000 соседних
    ответ — десятки тысяч символов («не более 180 пар BC», «ровно 100 пар WW») двойной цикл не дождаться — «Подробнее: два указателя»
    корректное выражение, знаки «−», «*» или «+», «−» (демо 2025, 2027, ЕГЭ 2024, 2026, Крылов) шаблон Б
    «порядок действий слева направо совпадает с правилами математики» сначала умножения, потом вычитания: num + r'(\*' + num + r')*(-' + num + r')*', поиск с каждой позиции
    числа — в 6-, 8-, 16-ричной системе цифры числа: 0|[1-5][0-5]*, 0|[1-9A-F][0-9A-F]*
    «значение выражения равно нулю» (ЕГЭ 2024, пересдача 2026) вкладка «Значение равно 0»
    «не более 40 (50) чисел» вкладка «Не более K чисел»
    самое длинное (большое) чётное / нечётное число в 12-, 14-ричной системе вкладка «Запись числа»
    ответ — номер первого символа числа m.start() того куска, который выбрали
    «правильная сумма сразу после буквы A», наибольший результат вкладка «Правильная сумма»
    самая длинная римская запись (ЕГЭ-2026) вкладка «Римские числа»
    цифра, буквы, та же цифра; гласных столько же, сколько согласных re.finditer(r'(?=([13579])([A-Z]+)\1)', s) — \1: «то же, что в первой скобке»
    «все буквы алфавита есть, цифр нет» re.split('[0-9]+', s), куски с len(set(x)) == 26
    файл из строк (2021–2022): «в скольких строках E больше A», «какая буква чаще всего после A» for x in open(…): x.count, словарь-счётчик

    Файлы к шаблону А и вкладкам — свои, их можно скачать и попробовать: stroka.txt (цифры и буквы — шаблон А, «Минимум», «Соседние символы», «Запрещённое сочетание», «Запись числа», «Два указателя»), vyrazh.txt, summy.txt, rim.txt, pary.txt. Сохраните рядом с программой под именем без 24-. Файл демоверсии — в архиве ФИПИ (ссылка выше), сохраните его как 24.txt.

    # №24, минимум: самая короткая подстрока, где буква Y встречается не менее 30 раз
# Ответ: 598
s = open('stroka.txt').readline().strip()
p = [i for i in range(len(s)) if s[i] == 'Y']    # где стоят Y
k = 30
print(min(p[i + k - 1] - p[i] + 1 for i in range(len(p) - k + 1)))   # от одной Y до 30-й

    Самая короткая подстрока с 30 буквами Y начинается и кончается на Y. Поэтому достаточно списка позиций всех Y: окно от p[i] до p[i + 29], длина p[i + k - 1] - p[i] + 1. Подстрока вместо буквы (пара TT, тройка ABC) — позиции её начал: s[i:i + 2] == 'TT', длина окна p[i + k - 1] + 2 - p[i] (последнее вхождение — целиком).

    Двойной цикл для минимума не годится: каждая проба — новый срез, и программа не закончится.

    # №24, соседние символы: самая длинная подстрока, где буква не стоит рядом с буквой, а цифра — с цифрой
# Ответ: 15
s = open('stroka.txt').readline().strip()
cur = mx = 1
for i in range(1, len(s)):
    a, b = s[i - 1], s[i]
    if a.isdigit() != b.isdigit():        # соседи разного вида: буква и цифра
        cur += 1
    else:
        cur = 1                           # серия начинается заново с символа s[i]
    mx = max(mx, cur)
print(mx)

    cur — длина серии, которая кончается на s[i]. Подходит пара s[i - 1], s[i] — серия растёт; не подходит — новая серия начинается с самого s[i], поэтому cur = 1, а не 0 (с нулём — 14 вместо 15). Максимум обновляем на каждом шаге, иначе потеряется серия в конце файла.

    Условия пары: a != b — соседние различны; a + b not in ('KL', 'LK') — нет KL и LK; not (a in 'ABC' and b in 'ABC') — никакие две из A, B, C не рядом; a > b — цифры убывают.

    # №24, запрещённое сочетание: самая длинная подстрока, в которой нет 2026
# Ответ: 463
s = open('stroka.txt').readline().strip()
s = s.replace('2026', '202 026')          # разрываем: 202 остаётся слева, 026 — справа
print(len(max(s.split(), key=len)))

    Нельзя, чтобы подстрока содержала 2026 целиком, а его части — можно: 202 остаётся в куске слева, 026 — в куске справа. Если делить просто s.split('2026'), получится 457 вместо 463 (на ЕГЭ-2021, XZZY: 1707 вместо 1713). Для «нет двух нулей подряд» — while '00' in s: s = s.replace('00', '0 0'): один replace не разорвёт «000».

    # №24, пары подряд: сколько пар AB или CB (в любом порядке) идут подряд
# Ответ: 19
s = open('pary.txt').readline().strip()
s = s.replace('CB', 'AB')                 # обе пары — одинаковые
k = 1
while 'AB' * k in s:                      # есть k пар подряд — пробуем k + 1
    k += 1
print(k - 1)

    Две разные пары заменяем одной, дальше растим k, пока в строке есть k пар подряд. «Согласная + гласная»: сначала все согласные → C, все гласные → A, потом ищем 'CA' * k. Спрашивают число пар — не умножайте на 2; если спрашивают символы — умножьте.

    # №24, запись числа: самое большое нечётное число в 12-ричной системе (цифры 0–9, A, B) — сколько в нём цифр
# Ответ: 18
import re

s = open('stroka.txt').readline().strip()
# первая цифра — не 0, последняя — нечётная (основание 12 чётное: чётность — по последней цифре)
num = r'[1-9AB][0-9AB]*[13579B]|[13579B]'
print(max(len(m.group()) for m in re.finditer(num, s)))

    Число: первая цифра — не 0, дальше любые цифры этой системы, последняя — нужной чётности. Основание чётное (12, 14, 16) — чётность числа = чётность последней цифры (A = 10 — чётная, B = 11 — нечётная). Самое большое число — самое длинное. Однозначные числа — отдельной веткой |[13579B]. Нужен номер первого символа — m.start() вместо длины.

    # №24, значение выражения равно нулю: самое длинное корректное выражение (знаки + и *), равное 0
# Ответ: 37
import re

s = open('vyrazh.txt').readline().strip()
num = r'(0|[1-9][0-9]*)'
pr = r'(' + num + r'\*)*0(\*' + num + r')*'   # произведение, в котором есть множитель 0
expr = pr + r'(\+' + pr + r')*'               # сумма таких произведений равна 0
print(max(len(m.group()) for m in re.finditer(expr, s)))

    Все числа неотрицательные: сумма равна 0, только если каждое слагаемое (произведение) равно 0, то есть в каждом произведении есть множитель 0. Так и записано: pr — произведение с обязательным 0, выражение — сумма таких произведений. Проверять eval самое длинное выражение нельзя: нулевым может быть кусок внутри него.

    # №24, «не более K чисел»: самое длинное корректное выражение (знаки + и *), в котором не более 5 чисел
# Ответ: 49
import re

s = open('vyrazh.txt').readline().strip()
num = r'(0|[1-9][0-9]*)'
expr = num + r'([+*]' + num + r'){0,4}'       # первое число и ещё не более 4 «знак число»
print(max(len(m.group(1)) for m in re.finditer('(?=(' + expr + '))', s)))   # поиск с каждой позиции

    Обычный finditer ищет следующий кусок после конца предыдущего. Здесь самое длинное выражение может начинаться внутри уже найденного (5 чисел с середины), поэтому ищем с каждой позиции: (?=( … )) и m.group(1). Без этого — 47 вместо 49.

    # №24, правильная сумма: после буквы C — числа со знаками + и −; наибольший результат такой суммы
# Ответ: 3376
import re

s = open('summy.txt').readline().strip()
mx = None
for m in re.finditer(r'C([0-9]+([+-][0-9]+)*)', s):
    acc = 0
    for t in re.findall(r'[+-]?[0-9]+', m.group(1)):    # числа со своими знаками
        acc += int(t)
        if mx is None or acc > mx:                       # сумму можно оборвать перед любым знаком
            mx = acc
print(mx)

    «Правильная сумма» — и любое её начало: в 12+5-100 есть сумма 12+5 с результатом 17. Если считать суммы только целиком, получится 2744 вместо 3376. Если в задаче одни «+», длиннее — всегда больше, и сумму можно брать целиком: sum(int(t) for t in x.split('+')).

    # №24, римские числа: самая длинная корректная римская запись; из равных — наименьшее число; ответ — число
# Ответ: 2814


def rim(n):                                   # число → римская запись
    znaki = [(1000, 'M'), (900, 'CM'), (500, 'D'), (400, 'CD'), (100, 'C'), (90, 'XC'), (50, 'L'),
             (40, 'XL'), (10, 'X'), (9, 'IX'), (5, 'V'), (4, 'IV'), (1, 'I')]
    r = ''
    for v, z in znaki:
        while n >= v:
            r += z
            n -= v
    return r


s = open('rim.txt').readline().strip()
chisla = sorted(range(1, 4000), key=lambda n: -len(rim(n)))   # длинные записи — первыми, равные — по возрастанию
for n in chisla:
    if rim(n) in s:
        print(n)
        break

    Правила римской записи писать не нужно: функция rim переводит число в запись, и записей всего 3999. Сортируем числа по длине записи (длинные — первыми; sorted сохраняет порядок равных, поэтому из равных первым идёт меньшее число) и ищем первую запись, которая есть в строке. Длиннее — не значит больше: XXXVIII (38) длиннее L (50).

    Подробнее: два указателя — когда двойной цикл не дождаться

    Если ответ — десятки тысяч символов («не более 240 пар DE» на ЕГЭ-2024 — подходит весь файл, 970 249), двойной цикл делает срезы такой длины миллионы раз и не заканчивается. Тогда окно двигают двумя указателями: правый край идёт по строке, левый догоняет, когда условие нарушено.

    # №24, два указателя: самая длинная подстрока, где 2026 встречается не более 100 раз
# Ответ: 7130
s = open('stroka.txt').readline().strip()
sub, k = '2026', 100
l = n = mx = 0                            # окно s[l..r]; n — сколько раз sub целиком в окне
for r in range(len(s)):
    if r - 3 >= l and s[r - 3:r + 1] == sub:     # справа закончилось новое вхождение
        n += 1
    while n > k:                                 # слишком много — сдвигаем левый край
        if s[l:l + 4] == sub:                    # слева уходит вхождение
            n -= 1
        l += 1
    mx = max(mx, r - l + 1)
print(mx)

    «Ровно K» для максимума — то же самое, только длину запоминают при n == k. Минимум «не менее K» — while n >= k: запомнить длину, потом сдвинуть левый край.

    Подробнее: старые разновидности (2021–2023)
    • Цепочка «XYZXYZ…», последний фрагмент неполный: счётчик cur, следующий символ должен быть 'XYZ'[cur % 3]; иначе, если это X, — новая цепочка cur = 1.
    • Разделители, которые накладываются (любая перестановка A, B, C — BCABC это три разделителя): replace не подходит — пометить символы каждой такой тройки списком bad и искать серию непомеченных.
    • «Группы от E до E без других E, не короче 12»: список позиций E, кусок s[p[i]:p[i + 1] + 1].
    • Файл из строк: for x in open('24.txt'), в каждой строке x.count(…); «буква, чаще всего стоящая после A» — словарь-счётчик и max(d, key=d.get).

    Типичные ошибки¶

    Скрытые ловушки — проверены запуском

    • finditer не видит выражений, которые начинаются внутри найденного. В «порядок действий слева направо совпадает с правилами математики» (Решу ЕГЭ 78049) кусок …−0 обрывается на «*», но с этого нуля начинается новое 0*…: обычный finditer даёт 46, с поиском с каждой позиции — 51 (ответ). То же при «не более K чисел» (47 вместо 49) и в цепочках из одинаковых пар (BB или DD). Ищите (?=( … )) и берите m.group(1). Для обычного выражения (демоверсия) разницы нет — проверено на 4000 случайных строк.
    • count не считает наложения. 'TTTT'.count('TT') = 2, а пар TT там три. Задачи «пара TT встречается 150 раз», «пара WW — 100 раз» (ЕГЭ-2023) так не решить: позиции пар — s[i:i + 2] == 'TT'. Для 2025, CAT, DE, BC наложений не бывает — там count верен.
    • Антиусловие должно быть необратимым. break при «2026 меньше 15 раз» — и программа печатает 0 вместо 2662: на коротком начале вхождений всегда мало.
    • В условие — всё, что требуется. Если «нет буквы A» стоит только в антиусловии, а в условии одно «не менее трёх E», в ответ попадают куски с A: на задаче Решу ЕГЭ программа ушла в долгий счёт с неверным ответом.
    • В «или» длинный вариант — первым. Регулярка берёт первый подошедший вариант: ([678]|[678][0678]*[678]) остановится на одной цифре (Решу ЕГЭ 69932: 11 вместо 40), верно — ([678][0678]*[678]|[678]). В 0|[1-9][0-9]* порядок не важен: число с нуля — только сам 0.
    • Ноль — отдельной веткой, ведущие нули — нельзя. Без 0| на демоверсии 128 вместо 154, с числами [0-9]+ (ведущие нули разрешены) — 156.
    • re.findall со скобками возвращает не куски, а содержимое скобок: на демоверсии «самым длинным» окажется кортеж из трёх частей. Пользуйтесь finditer и m.group().
    • Правильная сумма — и любое её начало. С «−» максимум бывает у обрывка суммы: Решу ЕГЭ 76692 — 219, если брать суммы целиком, ответ — 221; на нашем файле 2744 против 3376.
    • Минимум: + 1 и k - 1. p[i + k - 1] - p[i] без + 1 — 597 вместо 598, p[i + k] - p[i] — уже 31 буква Y (638).
    • Запрещённое сочетание — края отдать соседям. split('2026') — 457 вместо 463.
    • Серия начинается с 1, а не с 0 — иначе на 1 меньше (14 вместо 15).
    • Медленно — не значит неверно. Двойной цикл на файле в 10 млн символов думает 25–50 с. Но если ответ — десятки тысяч символов, ждать бесполезно: каждый шаг цикла — срез длиной в ответ. Замерено на сборнике Крылова 2026 (5 млн символов): «оканчивается на CAT, цифра 1 ровно 700 раз» (ответ 25 356) — 24 минуты, «на DOG, цифра 2 ровно 300 раз» (11 487) — 17 минут; окна между соседними цифрами — 2 с. Правило: нет ответа за 2–3 минуты — остановите программу (Ctrl+C) и возьмите быстрый способ: окна между позициями (строка про CAT в «Разновидностях») или «Подробнее: два указателя».
    • Условие задачи читать до конца. В сборнике Крылова (2026, вариант 8) «шестнадцатеричные цифры» — числа 16-ричные: 768, а по-десятичному — 35. В варианте 6 знак перед первым числом условием не разрешён: ответ 166; 167 получится, если начать выражение с [+-]? (так в одном из видеоразборов). «Натуральные числа» — без нуля (КомпЕГЭ: 40, с нулём — 51).
    • readline() оставляет \n в конце строки — пишите .strip().
    • max(куски) без key=len сравнивает строки по алфавиту, а не по длине.
    • Пары или символы? «Количество пар» — не умножайте на 2; «количество символов» — умножьте.
    • Латинские буквы. В условии на сайте буква «Т» бывает набрана кириллицей (в сборнике Крылова — А, В, С, Е), в файле — латинские: в коде пишите латиницей.
    • Не открывайте файл в редакторе — 10 МБ в одной строке IDLE и Блокнот «вешают». Свой пример для проверки возьмите из начала файла: print(s[:200]).
    • Скобка ( в регулярке без пары — re.error: missing ); знак + или * как символ — \+ или [+*].
